# WhaleLife

WhaleLife 是一个在本机运行、通过插件扩展能力的 AI 伙伴框架。你可以选择模型、编辑人格，在网页里与它聊天，再按需接入 QQ、网页浏览、B 站和视听理解等能力。

WhaleLife 交流 QQ 群：**962935021**

主干负责模型配置、人格与记忆、插件运行、日志和权限；具体能力由各自独立的插件提供。

- **延续交流**：网页与渠道插件使用同一会话时，可以接着之前的内容聊；切换人格不会自动新建会话。
- **自己决定何时整理记忆**：自动整理为日记默认关闭，需要时可按上下文占用比例开启。有效日记替代对应原文进入上下文，原始记录仍保留。
- **按需添加能力**：先完成本地聊天，再安装需要的插件；在控制台管理插件设置与启停。

## 开始使用

### 新手推荐：让 DSH 帮你安装

1. 从 [DeepSeek 官网](https://www.deepseek.com/download/) 下载并安装页面上方的 **DeepSeek Harness（DSH）桌面版**。
2. 配置好 DSH 后，新建对话，把下面这段话发给它。

   ```text
   请帮我安装 WhaleLife，只装主干。项目地址是 https://github.com/iinukami/whalelife 。装好后帮我启动，把控制台的网址发给我。
   ```

### 手动安装

1. 下载本仓库源码，安装 **Node.js 24 或更新版本**，用 `node --version` 确认版本。
2. 在项目目录打开终端，执行 `npm ci` 安装依赖。
3. 首次使用时创建 `config` 文件夹，将根目录的 `config.example.json` 复制为 `config/config.json`。升级已有安装时保留原配置。
4. 执行 `npm start`；Windows 也可以双击 `start.bat`。打开 [本地控制台](http://127.0.0.1:9270)。
5. 在“模型服务”添加服务连接和聊天模型，在“使用配置”选择模型与人格，然后到“对话”页开始聊天。已提供默认人格“鲸鲸”，可以在“人格”页编辑或新建。

模型服务可配置云端或本地的 OpenAI 兼容接口，具体模型需支持所用的对话及工具调用能力。首次启动会初始化记忆目录和缺失的默认人格文件，无需提前准备聊天记录。

默认仅供本机访问。需要局域网访问时，在配置中开启 `web.lan_enabled` 并设置密码。模型与人格选择保存后供后续对话使用；端口等启动参数变更后需重启。终端中按 `Ctrl+C` 退出。

### 更新 WhaleLife

在控制台「概览」查看本机版本，点「检查更新」才会查询 GitHub 正式发行版。发现新版时，点「查看更新」可先读发行说明。点「更新并重启」后，WhaleLife 才会下载发行包、校验大小和 SHA-256，并在旧版仍提供服务时核对安装目录的启动器能否安全试运行新版。检查通过后才关闭旧版、备份资料并试运行新版。从原装 v0.1.1 更新时，系统会在预检通过后自动迁移启动器。下次本体更新仍可直接在概览确认。如果需要替换的启动文件有自定义改动，或文件正在被其他程序占用，控制台会提示原因。设置了控制台密码的用户，重启后请重新登录查看结果。

更新保留已安装插件、启停状态、图库、配置、人格和记忆。请留出足够空间备份本机资料。新版先检查核心启动、原活动插件的清单和入口。预检失败会恢复旧版和升级前的资料，先让控制台重新可用，再在后台清理已退役的备份。其他进程仍占用的备份会在解除占用后重试清理。通过预检并写入版本选择后才会运行插件、开放服务。从这一步起，即使启动失败，也会保留现场资料，避免覆盖新会话或重放插件任务。若记忆或人格指向实例外的路径，或待备份目录含有链接，控制台会说明原因并继续使用旧版。

日常主干提交可以累积到一次发布。每次正式发布都会提高本体版本号，控制台据此提示更新。首次从公开的 v0.1.0 升级，请先关闭 WhaleLife，按原安装方式更新程序源码和依赖，再从原安装目录启动。保留自己的配置、人格、记忆和插件目录。之后即可在控制台更新。插件商店会单独刷新目录，新插件收录后即可被搜索到。[本体发布流程](architecture/RELEASING.md#本体发行包)

## 插件

从 WhaleLife 概览或「插件管理」点「插件商店」，即可在当前页浏览官方和社区插件。点「关闭商店」会回到打开商店的位置。官方插件的安装按钮旁会显示适用版本。有依赖时，商店会先列出将安装、启用或沿用的插件。确认后，WhaleLife 从 GitHub 下载缺少的发行包，核对大小和 SHA-256，再安装并启用。重复安装可复用已校验的本机缓存。[官方发行包说明](market/official-builds.md)

已安装的官方插件可以在「插件管理」中设置、启停或卸载。点「卸载」时，如果还有其他插件依赖它，弹窗会列出名称。卸载图库会保留原图、标签和配置，重装后可以继续使用。

通过商店安装的社区插件也可以在「插件管理」卸载。点击父插件的「卸载」，确认框会列出随这份发行包一起移除的子插件。单独安装的子插件有自己的卸载入口。若还有插件依赖其中任何一项，先按弹窗列出的名称处理依赖。卸载只移除经核对的程序文件，保留父子插件的配置和用户数据。遇到改动过的程序或无法确认归属的文件，弹窗会说明原因。

在左侧「插件页面」右键点击插件名，选择「置顶」或「取消置顶」。触屏可长按插件名。使用键盘时，按 Tab 移到插件名，再按 Shift+F10 打开菜单。已置顶的插件名旁会显示小图钉。最近置顶的插件排在最前，刷新后当前浏览器会记住顺序。

通过商店安装或更新官方、社区插件后，无需重启 WhaleLife。运行中的插件会自动加载新版，原本停用的插件更新后仍保持停用。

使用默认端口可[打开控制台里的插件商店](http://127.0.0.1:9270/#market)，在 GitHub 上也可以[浏览插件目录](market/README.md)。

更新已装插件时，在商店里点「检查插件更新」，再点对应插件的「更新到 vX」。确认框会列出新旧版本，以及需要安装、启用或沿用的依赖。商店在确认时重新核对审核记录，只替换可确认归属的程序文件，保留配置、数据和原来的启停状态。依赖版本不兼容时会提示先处理依赖。更新失败时，控制台会显示失败步骤和撤回结果。官方和社区插件都使用这个流程。

各插件独立维护，安装和配置方法见对应仓库。按插件说明使用发行包或构建产物，无需把整个源码仓库放进 `plugins`。

| 插件 | 能力 |
| --- | --- |
| [QQ](https://github.com/iinukami/whalelife-plugin-qq) | 在 QQ 收发消息，与当前会话衔接 |
| [QQ 空间](https://github.com/iinukami/whalelife-plugin-qzone) | QQ 空间浏览与互动，作为 QQ 的子插件安装 |
| [自主性](https://github.com/iinukami/whalelife-plugin-autonomy) | 管理意图与主动行动，按配置调用已有能力 |
| [图库](https://github.com/iinukami/whalelife-plugin-gallery) | 管理图片，供模型查看和其他插件使用 |
| [网上冲浪](https://github.com/iinukami/whalelife-plugin-surf) | 搜索网页、阅读正文、沿链接继续浏览 |
| [B 站](https://github.com/iinukami/whalelife-plugin-bilibili) | 搜索与浏览视频、按配置互动，作为网上冲浪的子插件安装 |
| [视听理解](https://github.com/iinukami/whalelife-plugin-vision) | 准备图片、视频片段和声音证据，供当前模型理解 |

QQ 空间依赖 QQ，B 站依赖网上冲浪；媒体处理等可选能力和资源要求以各插件说明为准。

### 社区插件投稿与审核

社区插件由原作者发布和维护。新投稿通过发行包审核后收录。商店有适合本机的已审核发行包时，可以在控制台点「安装」，预览依赖和版本后确认。此前仅提供「安装说明」的已收录条目仍可使用。

**作者如何投稿**

1. 把插件放在公开的 GitHub 仓库。在 README 或单独的安装文档中，写清安装步骤、必需依赖，以及安装后怎样试用主要功能。如果插件需要读取本地文件、使用账号或访问网络，也请说明用途。
2. 用 WhaleLife 打包工具生成 `.wlpkg.gz`，上传到自己仓库对应版本的正式 GitHub Release。在发行说明中列出文件名、字节数、SHA-256、适用的 WhaleLife 版本、系统、架构和必需插件版本。[打包命令与格式说明](market/community-packages.md#作者打包)
3. 在主仓的「提交社区插件」Issue 填写**公开仓库链接**、**发行包附件下载链接**和**一句话介绍**。附件链接应指向该版本的 `.wlpkg.gz` 文件。已开帖但尚未发包的投稿保持待补件，请在原 Issue 补充链接，通过审核后收录。[填写投稿表单](https://github.com/iinukami/whalelife/issues/new?template=submit-plugin.yml)
4. 「插件图标链接」可留空，此时使用默认图标。想用自定义图标时，把 PNG 放进自己的插件仓库，将图片文件链接填在这一栏。推荐 256 × 256 像素的方图，最大 1 MiB，每边不超过 1024 像素。通过审核后，商店列表、详情和插件管理页会使用同一张图。

已收录的插件可以单独换图。作者在主仓提交图标审核帖，填写仓库、完整插件 ID 和新图链接。已有开放的图标审核帖时，在该帖补充即可。仅审图标，无需升版或重新打包。[提交图标审核](https://github.com/iinukami/whalelife/issues/new?template=review-plugin-icon.yml)

**已收录插件如何发新版**

提高 `plugin.yaml` 的版本号，在插件仓库发布对应的正式 Release 和 `.wlpkg.gz`，再由作者**在 WhaleLife 主仓为这个版本新开复审 Issue**。例如标题写 `[复审] 日程 v1.2.0`，填写插件仓库、完整插件 ID、版本、Release 页面和安装包直链。原投稿链接选填。维护者从主仓开放的审核帖接单。[提交新版复审](https://github.com/iinukami/whalelife/issues/new?template=review-plugin-update.yml)

同一插件、同一版本已有开放审核帖时，在该帖补充说明或纠正链接。已发布的附件内容如有改动，即使只改打包，也须升版、重新发布正式 Release，并按新版本提交复审。

维护者在独立环境试装每个新版发行包，再将通过审核的版本及兼容条件登记到商店。用户手动点「检查插件更新」时，只提示比已装版本更新且适合本机的已审核版本。旧版控制台可能在作者发布 Release 时就显示「有更新」，可从商店核对已审核版本。仅提供安装说明的条目仍可在商店找到。[社区插件打包和审核步骤](market/community-packages.md)

**维护者如何审核**

1. **核对仓库。** 确认仓库公开，对照 `plugin.yaml` 核对插件 ID、名称、版本和依赖，并检查目录中是否已有相同 ID 或容易混淆的同名条目。
2. **试装并反馈。** 从作者的正式 Release 下载提交的发行包，核对字节数、摘要和兼容条件，在独立环境试装，验证宿主兼容性和基础功能。遇到安装失败、依赖遗漏或权限用途不清时，在审核 Issue 写明复现步骤或需要补充的内容，待作者更新后复核。
3. **收录并验收。** 审核通过后，维护者将插件资料、首次收录日期和已测附件的 `verifiedReleases` 记录写入公开目录的 `community` 列表。维护者处理主仓开放的投稿和复审 Issue，按插件仓库和完整 ID 对应商店条目，按版本对应本次申请。更新进入 `main` 后，在商店的「全部」和「社区」分别按插件名和 ID 搜索，核对安装入口，在审核 Issue 告知作者结果并结案。[查看公开目录](market/catalog.json)

收录后，插件的更新和故障修复由原作者负责。仓库临时无法访问时，维护者会稍后重试。确认仓库已删除或转为私有后，维护者会撤下条目，在原 Issue 记录原因与首次收录日期。作者可在主仓提交复审申请，附上新的公开仓库地址和原投稿链接，复核通过后按原收录日期恢复。
