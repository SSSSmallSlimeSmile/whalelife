# WhaleLife 主干现状与开发说明

核对日期：2026-11-19。插件独立执行、公开契约及统一模型连接已完成；已有Web与插件共用当前会话、时间上下文、通用会话文档、统一会话执行队列、临时及多模态工具隔离、渠道轮内追加。记忆使用有效日记与未覆盖原文衔接，自动日记默认关闭；开关仅控制今后的生成，已有有效日记继续使用。已确认直接出站的完整正文进入同会话助手历史，旧sent回执只读兼容，不依赖短经历召回。验证记录及边界见第6节。

新增默认关闭的本地诊断输出：完整采集主干实际掌握的模型请求、响应、原始用量与会话/工具关联，独立目录长期保留，不改变记忆或请求，不依赖查看工具。插件自行发起的 HTTP 不在覆盖范围。配置、协议及故障边界见[诊断输出](DIAGNOSTICS.md)。

**本文是主干整体状态的唯一入口**，说明已经做了什么、现在怎样运行、代码为何这样组织，以及现存问题。接口细节见[PLUGINS.md](PLUGINS.md)，记忆算法见[MEMORY.md](MEMORY.md)，现有渠道接口见[CHANNELS.md](CHANNELS.md)。旧设计稿和阶段报告是历史材料，不能作为另一份当前任务清单。

同一会话的多位渠道发言人按各自的平台账号区分。聊天和历史按条使用当时的发言人资料；渠道插件可提供昵称、联系人备注。插件接入契约见[入站发言人](CHANNELS.md#入站发言人)。

## 1. 当前结论与固定边界

当前已有本地聊天、人格、文件记忆和管理控制台。已安装插件独立执行、具备故障切割；公开接口有独立数据契约、加载前API检查和冻结旧插件回归。模型连接可供插件按配置ID读取。主干已具备进入插件开发的基础，本轮不再扩展平台或主动性业务。

控制台概览和「插件管理」页都可以打开「插件商店」抽屉，浏览[主仓插件目录](../market/README.md)、投稿并安装本机适用的官方版本。关闭商店会回到原页。已安装插件的启停、设置和卸载集中在「插件管理」。父插件和子插件分别核对文件归属和依赖，点击卸载才显示确认或拦截原因。安装时，宿主先获取并校验计划所需的全部 GitHub 发行包，再修改插件目录或启用依赖。下载来源及本机缓存格式见[官方发行包说明](../market/official-builds.md)。

社区插件的卸载以本机安装的发行包为单位。管理页读取本地安装信息，点击卸载时核对发行包清单、程序文件和依赖关系。随包组件列在父包的确认框，独立安装的子包单独管理。确认后保留各组件的配置和数据。

用户在插件管理或商店点「检查插件更新」后，两处会显示已安装插件的「有更新」提示。商店提供「更新到 vX」按钮，预览版本、依赖和附加组件后再确认。宿主重新读取主仓已审核的发行资料，校验文件归属、兼容性和计划摘要，在同一安装事务中切换程序、保留配置和数据。新版加载失败时恢复旧版和原启停状态。官方清单和社区目录分别登记审核通过的发行包。已收录社区插件的作者在主仓为新版提交复审 Issue。维护者从开放的审核帖核对申请，再检查帖子指定的 Release 和附件。打开商店仍会读取公开目录，显示新收录的插件。

宿主进程在更新中退出时，下次启动先核对本地事务记录和安装回执，再扫描插件。已提交的更新继续使用新版。尚未提交的更新恢复旧程序和资料，并撤回本次依赖改动。现场文件已被其他程序改动、无法判断归属时，宿主会保留备份并在日志中标明位置。

控制台概览显示本机版本与更新状态。用户点「检查更新」才会查询官方 GitHub Release。确认后下载并校验独立程序包。当前实例继续提供服务，直至启动器兼容性检查通过，才使用本实例的进程和锁切换。原始安装目录提供稳定启动入口，插件与用户资料继续使用原路径。升级前保存资料快照，预检期间检查核心、原活动插件的清单和入口，用户接口保持关闭。预检进程退出并持久写入新版本选择后，正式进程才恢复中断的插件更新、加载插件并开放服务。预检失败时恢复原快照并启动旧服务，已退役快照独立延后回收。对于原装 v0.1.1 启动器，最后一轮插件预检通过后，宿主会保存原入口并安装经过内容校验的新启动器。原启动进程继续负责停止本实例，后续确认更新和冷启动都使用新的预检与回滚流程。接管后发生故障则保留当前资料。[使用说明](../README.md#更新-whalelife) · [本体发行包](RELEASING.md#本体发行包)

社区插件的安装资格按具体发行附件审核。控制台从公开主仓目录取得版本、兼容条件、依赖、附件大小和 SHA-256，用户确认时再次核对审核记录。安装步骤与官方插件共用文件归属检查、串行事务和失败回滚。已安装社区插件的必需依赖记录在本地，插件停用时仍会阻止误卸依赖。没有审核附件的条目保留原作者的安装说明。[社区发行包与审核](../market/community-packages.md)

用户确定的主干职责只有五块：

| 职责 | 范围 |
| --- | --- |
| 模型 API 配置 | 服务连接、密钥、模型条目、参数、模型选择和插件使用这些配置的入口 |
| LLM 人格与记忆 | 人格、会话、事实、经历、摘要、认知、检索、上下文及现有 token 统计 |
| 插件运行与调用 | 加载、启停、依赖、能力注册、调用、取消和故障切割 |
| 日志与权限 | 记录行为和结果，按用户授权允许或拒绝调用 |
| 统一配置与管理入口 | 公共设置、插件配置存储、控制台和插件页面入口 |

驱动人格、记忆和工具所需的对话请求归主干。QQ/微信/B站接入、外部发送、主动性、意图与计划、语音/图像等具体能力、向量召回、插件业务频率/预算/重试归插件。配置某种模型，不等于主干必须实现对应业务。

意图相关主干仅提供通用会话文档读写：按插件/会话隔离、原子保存及版本冲突检查，不参与自动召回。文件格式、产生、上下文注入、唤醒和执行全部由自主性插件管理；没有该插件就没有意图生成。不内置专用插件ID或自主调度。

完整会话另支持runTransient临时输入，不写成真人消息或未来记忆；默认run不变。已有技术输入可由原插件按消息ID明确排除，原始档案保留；日记只失效引用了变化来源的篇目，旧摘要/自动认知保留原有排除兼容。它们是通用会话/记忆契约，不含自主唤醒、用户抢占或静默结束业务。默认记忆列表已按合并来源的记录时间排序后截取。

思考模式工具链支持reasoning_content的流式收集及当轮回传，兼容部分接口返回的字符串reasoning别名；标准字段优先，不重复拼接，也不凭reasoning_tokens补造思考内容。临时输入开启新协议轮次，带工具的思考模式将缺少协议思考字段的既有历史作为保留角色/来源的引用提供；不改原文、不关闭思考、不存思考过程为记忆。模型失败响应增加限量、非正文回显的安全诊断。该修复不重放已失败的插件任务或约定。

会话执行现由统一内存队列协调Web、渠道入站和插件enqueue/enqueueTransient；同会话串行，不中断在途操作，不同会话可并行。可选优先级、插件实例内等待项去重、signal取消及执行前有效性检查均为通用机制；不加入自主性业务。旧run/runTransient保留忙时拒绝语义，插件可独立接入新接口。正式插件未由本轮代改，队列不跨重启重放。

渠道兼容新增可选openTurn：插件显式将同账号、peer和sender的补充加入正在等待、生成或执行工具的同一轮，保留每条消息ID和接收时间。已开始动作不撤销，当前批次剩余工具按补充重新判断；最终候选前原子封口，整轮只投递一次最终回复。首条与成员共享最终投递结果，取消/崩溃保留各自输入核对依据、不自动重放；旧receive和sessions各入口不变。接入须特性检测，归并与提前收件确认仍由插件负责，未代改正式平台插件。

主干升级不得要求已有合规插件同步修改；插件升级不得要求修改主干或无关插件。提供方负责维持公开契约。插件可以出错，但主干须能切割它，让无关功能继续运行。完整约束见[AGENTS.md](../AGENTS.md)。

扩展服务现支持optionalDepends声明与ctx.optional订阅。可选提供者缺失、停用或故障不会级联停止消费者；连接、在途等待与绑定资源失效，恢复后通知新实例。现有depends/get强依赖语义不变，不增加平台判断或桥接插件记录；插件需显式接入新入口，既有桥接不由主干自动迁移。契约与接入示例见PLUGINS的“可选服务接入”。

控制台支持父插件manifest声明console.groupChildren:true，将子插件卡片和侧栏入口收进父级工作区；父级原有页面保留，子插件有独立设置、状态、启停与重载。未声明插件继续平铺，旧页面链接保留；收纳只影响展示，不合并运行实例。QQ等插件由其开发会话添加声明并发布，主干不代改正式插件。

以下“已实现”指有实际代码和调用路径。代码存在、测试通过、真实平台长期运行验证分别说明，不能相互替代。

## 2. 已经做成的功能

### 2.1 模型配置与对话请求

- 提供商连接与模型条目分开：连接保存地址、密钥、协议、代理、超时；一个连接可管理多个模型，各自设置名称、用途、参数和启停。
- 控制台可新增、编辑、删除配置，获取OpenAI兼容接口或DashScope原生接口的模型列表并批量添加，也能手动添加。DashScope原生连接按文本嵌入能力分页获取，千问对话/识图使用对话页的百炼兼容连接；获取列表不自动保存。配置ID与供应商实际模型名称分开。
- 按用途选择模型；人格专用对话模型优先，否则使用工作空间对话选择。缺少有效选择时提示配置，不自动选列表第一项。
- OpenAI兼容对话链路支持流式回复、工具调用、返回用量、超时、代理和取消。
- 空白最终回复按服务结束标记区分输出/上下文上限、过滤、资源不足、中止及仅有思考等原因；保持不自动重试、不重放工具、不保存空白助手历史，已有有效正文与真实用量记账不变。仅有思考不等于已证实额度不足，提示保留原因边界。
- 当次响应没有结构化工具调用时，主干识别正文里完整、独立且指向本次可用工具的 DSML 调用块，也识别缺少开头包装的完整 `invoke` 和把 `tool_calls` 拼成 `toolcalls` 的包装。界面和后续模型上下文在对应位置显示未执行提示，普通会话可展开查看模型原文。代码示例、引用和识别不清的文本保留原样。对于旧助手记录，可在「记忆管理 → 会话档案 → 查看」逐条预览、确认或撤销工具标记的隐藏。已确认的历史记录沿用用户当时看到的预览，原始记录仍可查阅。
- 对话模型可单独保存思考字段读取/回传映射及默认关闭的缺失字段补空选项。AI 辅助配置以最多四次合成请求提出并验证文本映射，成功后填入草稿，保存才生效；日常聊天不额外调用模型来分析字段。已有模型的默认协议、记忆与用量行为不变，插件无须配套升级。范围及限制见[思考模式工具协议](PLUGINS.md)。
- 当前记忆机制通过官方DeepSeek接口对话时，稳定人格与完整历史保持在请求前部，动态事实、检索、来源及时间后置以提高前缀缓存复用；未知兼容服务和旧legacy路径保留原单system排列。控制台显示最近一次请求的缓存命中量及参考费用，缺失数字不当作零；计价适用范围与未知费用说明见[记忆说明](MEMORY.md#前缀缓存与参考费用)。
- 新增临时多模态工具入口：插件返回文字及PNG/JPEG/WebP字节，由主干转换成当前模型的真实图片内容块；沿用人格、工具续轮、临时资料隔离和供应商用量，不另选视觉模型。未安装此类插件时纯文字链路不变；下载、解码及视频抽帧仍归插件。限制和协议角色说明见[PLUGINS.md](PLUGINS.md#临时多模态工具2026-11-04兼容新增)。
- Embedding已有配置、绑定、连通测试和维度检测，支持OpenAI兼容接口与DashScope原生接口；当前记忆检索不使用Embedding。
- 密钥输入有显示/隐藏按钮；已保存密钥不回传浏览器。留空保留，明确操作才清除；更换带密钥连接的地址/协议需重新输入或清除密钥。
- 配置保存有版本冲突检查和原子替换。已保存的模型、人格选择供后续请求读取。
- 模型上下文容量优先使用手动值，否则按精确模型ID读取服务返回的显式容量字段；支持常见兼容服务元数据格式，失败或缺失保持未知，不按模型名称猜测。模型编辑器可自动获取，未知时可手动填写；上下文容量与输出token上限分开。容量缓存按连接、凭据和模型配置隔离。

插件可通过 models.connection(id) 获取各用途的连接和参数。用途含chat/embedding/rerank/image/stt/tts/custom，协议允许自定义标识；未知协议保留给插件执行，不能被选为核心聊天或伪装成核心可测试。配置语音、图像等条目不代表对应业务已实现。

代码：[model-config.ts](../core/model-config.ts)、[model-context.ts](../core/model-context.ts)、[model-http.ts](../core/model-http.ts)、[llm.ts](../core/llm.ts)、[models.js](../core/ui/models.js)。

### 2.2 人格、会话与上下文

- 人格可新建、编辑、保存、启用及指定专用模型；每轮读取当前人格正文。
- 人格与会话分开：切换人格保留会话和历史，显式新建才另起会话。档案记录最后使用的人格，原始消息保留当时的人格和版本。
- 当前会话由主干持久保存；使用配置中明确点击“切换会话”或“新建并使用”后，插件current及未指定会话的run使用同一选择，单独改变下拉选项不生效。概览、使用配置、记忆管理显示实际当前会话。首次迁移采用有效旧浏览器选择，否则用最近可用会话；全部为空才新建。并发初始化只建一份，进行中的回复保持原会话。
- 完整会话默认带当前时间、时区、星期、消息时间和交流间隔；工具后的继续请求刷新时钟。使用配置仅显示系统时间，时区编辑入口暂时隐藏，保留已有timezone配置（默认Asia/Shanghai）；保存模型和人格不改时区。历史、摘要和认知传递日期依据，具体规则见MEMORY；直接模型接口不注入这些信息。
- 记忆下拉框与档案“查看记忆”只改变浏览对象，不改变全局当前会话；所选档案的事实、上下文和设置按其ID读写，与聊天用量分开。会话档案可改名、确认删除；删除后进入回收目录。进行中的会话或记忆恢复会阻止冲突操作。
- 默认使用同一会话不同人格的历史，也可选择当前人格版本对应的历史范围；事实和历史开关继续保存。记忆由有效日记与未覆盖的完整原文衔接，没有日记时即为完整有效历史；不运行旧摘要/认知整理，也不按6000 token截尾。
- 自动日记（`diary_enabled`）默认关闭，开启后仅在容量达到可配置比例时将较早完整原文追加成新日记；默认触发80%、目标50%，均以预计输入加输出预留占模型总容量计算。关闭后已有有效日记继续使用，不恢复全部覆盖原文。没有7天或条数触发，不重新总结旧日记。超过容量仍无法处理时提示用户，保留原文和当前会话选择。
- 界面主要显示每轮更新的预计上下文百分比，并单列上次请求实际输入/输出及累计用量。预计值随当前资料和配置重新组装，不冒充服务精确计量；容量未知时保留未知并提供模型容量设置入口。

代码：[persona.ts](../core/persona.ts)、[persona-config.ts](../core/persona-config.ts)、[session.ts](../core/session.ts)、[session-context.ts](../core/session-context.ts)、[personas.js](../core/ui/personas.js)、[context.js](../core/ui/context.js)。

### 2.3 记忆

| 已实现内容 | 当前行为 |
| --- | --- |
| 原始经历 | 按会话、按月保存JSONL，默认记录对话、工具结果与来源；摘要和淡忘不删除原文 |
| 聊天与工作记录 | 普通聊天完整保留用户及最终助手正文；渠道直接出站确认sent后，全文按稳定ID进入同会话助手历史，旧回执只读投影，experience短预览留档但不重复召回。临时工具不抹掉提问/约定；工具原文与后续参数继续隔离。自动工具投影仅供审计；明确业务结果由recordExperience记录。技术执行runTransient保持临时资料规则，旧占位只留档不再进入上下文 |
| 共享事实 | 保留共同资料，用户可编辑，AI只读 |
| 独立事实 | 新会话默认为空；AI通过专用工具追加、替换或清空，整份正文硬上限100个Unicode码点，full也不能绕过。提示优先保存稳定背景，临时状态不推断为尚未完成的任务；无新信息/约定不据同一记录反复催促，不自动删除旧事实 |
| 记忆上下文 | 当前范围的有效日记加未覆盖的完整原文；已知容量不足时明确提示，不悄悄裁尾 |
| 自动日记 | 默认关闭；开启且达到容量阈值后一次请求整理较早原文，按篇追加，固定来源ID及版本；关闭后已有有效日记仍用于衔接 |
| 日记失效与失败 | 来源变化只影响引用该来源的篇目；生成或保存失败暂停当前范围，显式恢复后才再按阈值尝试 |
| 旧摘要与认知 | 原文、数据及既有管理接口保留；当前机制不注入旧摘要、不运行旧认知整理 |
| 检索与淡忘 | 本地分词/词频、相关性和时间降权；默认最多6条、约800估算token；明确查旧事可检索历史，不物理遗忘原文 |
| 显式共享 | 会话默认独立；跨会话需加入空间并明确分享记录，不自动共享全部历史 |
| 插件扩展 | 插件可记录实际经历、注册自己的记忆类型并保存状态；所属插件由主干绑定 |
| 管理操作 | 查看预计占比、上次实际用量、原文、逐篇日记、旧摘要/认知及事实；记忆检索服务端分页，默认25条、可调1–100条，支持页码跳转，按需请求；支持备份和恢复 |
| 数据保护 | 迁移前备份；恢复前校验并备份当前状态，失败回滚；恢复与正在进行的写入互斥 |

日记每次触发至多一次生成请求，只读本批原始记录，不递归重写已保存日记；内容以第一人称保留经历、约定、纠正和不确定理解，不另写事实、认知或意图。长度随材料决定，仍受请求输出与存储校验上限约束。截断、无效结果、来源变更或未节省容量不提交；非取消失败保留原文并暂停该历史范围，需用户显式恢复。核心整理沿用每会话每日默认20,000 token额度，预留与实际用量结算分开，不管理插件额度。

新样例默认 `diary_enabled: false`。旧 `memory_mode: full/diary` 保留为自动生成开关的兼容别名；未声明新开关但显式携带旧字段或 `legacy` 的调用继续旧语义。旧时间窗口、消息保底、历史预算、短期/长期调度仅在兼容路径使用，`legacy` 不作为界面模式。现有配置迁移须明确保存新开关；旧摘要保留查看，不隐藏注入当前机制。细节见[MEMORY.md](MEMORY.md)。

磁盘可保留完整档案，送给模型的仍是经过筛选和预算控制的片段。当前没有意图生成、计划执行或主动联系用户的功能；这些归主动性插件。

代码分工：[memory.ts](../core/memory.ts)管存储，[memory-engine.ts](../core/memory-engine.ts)管记忆规则和检索，[memory-diary.ts](../core/memory-diary.ts)及[memory-diary-state.ts](../core/memory-diary-state.ts)管日记生成、来源校验和暂停，[context-material.ts](../core/context-material.ts)组装上下文；[memory-lifecycle.ts](../core/memory-lifecycle.ts)及[cognition.ts](../core/cognition.ts)保留旧整理/认知兼容，[memory-tools.ts](../core/memory-tools.ts)提供有限记忆工具，[memory-admin.ts](../core/memory-admin.ts)管查看、维护和恢复。

### 2.4 插件宿主与调用

- Cordis管理插件树；plugin.yaml与index.ts接入，支持父子插件和服务依赖。
- 启停选择持久保存，重启保持。依赖暂不可用与用户主动停用分开；恢复依赖不擅自启用用户关掉的插件。
- 插件可注册工具、页面、HTTP接口、事件和资源清理。入口有插件归属；停用后工具/页面移除，旧实例的受管理接口拒绝新调用。
- ctx.models、ctx.personas提供选择项；ctx.sessions支持显式新建、读取当前会话，以及在指定或当前会话中复用人格、记忆、工具与统计。enqueue系列可等待会话执行位；旧的显式调用、忙碌拒绝与渠道绑定保持兼容。
- ctx.models.connection(id) 返回后端连接快照；控制台及元数据列表不回传已存密钥。
- ctx.llm.chat是直接模型调用，不自动添加人格/历史或执行工具；usage交给插件，不自动纳入会话账本。
- ctx.config保存本插件私有配置；ctx.web提供统一鉴权、设置按钮和导航入口，表单与业务由插件实现。
- 消息、记忆、工具和生命周期提供提交后通知；不是拦截器或可恢复任务队列。插件自定义事件带自身命名空间。
- 工具路径检查权限，记录结果并形成带来源的经历；工具完成不必然代表外部业务完成。

每个安装插件在自己的子进程内执行；启动/调用超时、心跳失联、进程退出、V8堆耗尽及未处理的工具/页面/事件错误会标记失败并撤销入口，取消在途请求，限时清理后终止进程。明确依赖的插件暂停，无关插件和核心继续工作。用户启停选择、配置和历史保留，故障不自动重放外部动作。可恢复的业务错误应由插件自行捕获并返回明确结果。

manifest.apiVersion 在 import 之前检查，省略仍按旧1.x兼容；公开Context使用独立数据类型而非内部实现类。新进程重载也刷新静态import子模块。同步配置和跨插件服务方法保留调用语义，Web处理器仍使用真实Node req/res，经主干鉴权转发。同步调用收到回复即登记其中的异步结果；嵌套回调和取消监听器再次调用RPC时，后续结果不会因等待项尚未登记而丢失。公开接口不变，错误仍交给原调用者，结束/超时按原有切割规则清理。

代码：[runtime.ts](../core/runtime.ts)管生命周期，[optional-services.ts](../core/optional-services.ts)管可选连接及绑定资源，[plugin-process.ts](../core/plugin-process.ts)、[plugin-worker.ts](../core/plugin-worker.ts)、[plugin-rpc.ts](../core/plugin-rpc.ts)、[plugin-http-bridge.ts](../core/plugin-http-bridge.ts)管隔离执行和转发，[plugin-api.ts](../core/plugin-api.ts)、[context.ts](../core/context.ts)、[plugin-compatibility.ts](../core/plugin-compatibility.ts)管公开契约与兼容检查。另见[plugin-state.ts](../core/plugin-state.ts)、[plugin-services.ts](../core/plugin-services.ts)、[plugin-events.ts](../core/plugin-events.ts)、[plugin-web.ts](../core/plugin-web.ts)、[tools.ts](../core/tools.ts)。

### 2.5 日志、权限与控制台

- 日志输出到终端、按天文件和控制台；日志服务遮蔽已登记模型密钥，配置接口不回传已存密钥。
- 渠道openTurn失败回执增加等待、生成/会话记录、回复回执保存、最终回复投递阶段与安全分类原因；未知异常不原样写入回执，临时资料仍遮蔽，原有状态枚举、去重、投递和取消规则不变。页面请求仅将已证实客户端断开记为info，插件/上游故障、超时和未知错误仍记为error，不靠文案匹配或单独的destroyed状态判断。
- 标准输出/错误流断开时仅停用对应终端输出，文件与控制台日志继续；日志序列化、订阅者和磁盘错误不再向业务链抛出。磁盘失败退避重试，连续五次失败后停用文件写入并提示，重启后重新尝试；不把未落盘的日志冒充已保存。
- 普通运行日志默认单文件上限10 MiB、总量100 MiB、保留14天；按大小轮转，并在启动及后续写入时清理超限/过期文件。可用`log.max_file_bytes`、`log.max_total_bytes`、`log.keep_days`调整。单条日志最多64 KiB，超长带截断标记；该限制只适用于普通运行日志，不改聊天记忆、`logs/executions`或独立诊断输出。升级前如需保留超限旧日志，应先归档。
- 真正的未捕获异常仍记录并退出，不将业务异常中的`EPIPE`一概忽略。退出流程防重入，正常信号、关闭异常和启动失败均有10秒退出兜底；截止依赖主线程事件循环可调度，不是对同步死循环的进程外强杀机制。
- off禁止工具，full按授权执行；ask中可直接放行的调用可运行，需要批准的调用没有队列和批准界面，目前拒绝。full不等于操作系统提权，也不能绕过数据规则。
- 控制台已有概览、模型服务、使用配置、人格、对话、记忆、插件管理和日志。插件管理只展示扩展；运行数按实际状态统计，模型数使用有效配置过滤口径。
- 插件页面可自动出现在设置按钮/导航中，停用后移除；页面容器不是恶意代码沙箱。
- HTTP和WebSocket有登录及来源校验，默认本机访问。当前会话选择及记忆在服务端；浏览器本地旧ID仅供首次迁移，后续以主干选择为准。

代码：[logger.ts](../core/logger.ts)、[permission.ts](../core/permission.ts)、[web.ts](../core/web.ts)、[app.js](../core/ui/app.js)、[views.js](../core/ui/views.js)、[memory.js](../core/ui/memory.js)、[extensions.js](../core/ui/extensions.js)。

### 2.6 已在主干中的通用渠道

[channels.ts](../core/channels.ts)已经包含平台/账号/对象到会话的绑定、入站去重、回复生成、外部投递、独立回执、显式重试与重绑。Web聊天也先经过它的Web入口，再进入Sessions。这不是单纯的包装函数。

平台认证与实际协议仍由插件提供。插件描述平台/动作，主干注入真实归属；来源随原文、检索、摘要、认知保存，没有QQ/B站/微信业务判断分支。生成完成与实际发送完成分开记录，不确定动作不自动重放。

已确认直接出站的完整正文作为同会话助手历史保存；重复调用只返回原投递结果并可补记缺失历史，保存失败不触发重发。旧档案中有正文且非transient的sent回执只读投影，不增加每轮迁移写入；旧人格版本未知时仅进入session范围。原experience短预览继续留档，已有全文时不重复召回。临时工具原文与runTransient技术输入继续隔离，入站回复不重复追加；直接发送和补记不调用模型、不虚增用量。实现见[channel-history.ts](../core/channel-history.ts)，具体边界见[CHANNELS.md](CHANNELS.md)。

按最新边界，会话接入与来源记忆属于公共能力，外部投递/回执/重试在主干中偏厚。此处记录现状，本次未搬迁或删除。未来调整归属必须保持旧接口及行为，不能让渠道插件同步重写。见[CHANNELS.md](CHANNELS.md)、[provenance.ts](../core/provenance.ts)。

## 3. 当前代码的组织和开发思路

### 3.1 运行形态与启动

当前为Node.js 24 + TypeScript应用，直接运行.ts；后端使用Node HTTP/WebSocket，前端是原生JavaScript/CSS。主进程管理核心服务，每个安装插件独占一个可终止子进程，其中worker执行插件，转发层维持同步接口。记忆与模型配置仍由主进程提供，没有拆成多个部署服务。Runtime.load的闭包路径仅供可信核心组装及测试，安装插件统一走loadPath隔离路径。

[index.ts](../core/index.ts)负责组装：读配置 → 建立日志/模型配置 → 初始化及迁移记忆、恢复摘要副本 → 准备人格 → 建立LLM、工具、会话和渠道 → 注册核心服务 → 启动Web → 扫描插件 → 发布就绪通知。

核心服务也经Cordis内置注册提供依赖，但不是用户可随意卸载的扩展。控制台隐藏内置服务只影响展示，它们仍在运行链路中。

### 3.2 一次交流的实际调用链

~~~mermaid
flowchart TD
  W[Web对话] --> CW[Channels.web]
  P[插件 sessions.run / enqueue] --> S[Sessions 会话服务及统一队列]
  E[外部渠道插件] --> C[Channels 绑定与去重]
  CW --> S
  C --> S
  S --> A[读取人格、模型、记忆和上下文策略]
  A --> M[组装有效日记与未覆盖原文并检查容量]
  M --> L[LLM 对话请求]
  L --> Q{是否调用工具}
  Q -->|是| T[Tools 权限检查与插件工具]
  T -->|结果加入本轮消息| L
  Q -->|否| R[保存最终回复与用量]
  R --> O[更新上下文占比并返回文本]
  O --> UI[Web界面]
  O --> PR[调用插件]
  O --> CP[Channels 投递与回执]
  CP --> D[插件发送函数]
~~~

实际顺序：固定会话/人格/权限/来源和接收时间，检查维护状态；Web、渠道和enqueue系列进入统一会话队列（旧run忙时拒绝），取得执行位后读取人格与模型；记录用户消息，组装事实、检索片段与当前范围的有效日记及未覆盖原文。启用自动日记且达到容量阈值时至多生成一篇，再重新检查容量；关闭开关不再生成，已有日记继续衔接上下文。始终预留输出空间，容量不足时明确提示，不按旧历史预算截尾。等待项也保护会话不被删除、重绑或恢复；调度实现位于[session-queue.ts](../core/session-queue.ts)。

模型要求调用工具时，主干检查权限、执行工具，将结果加入本轮请求；按用户确认不设固定轮数，软提示引导模型完成、明确受阻或没有新进展时收尾。权限、用户取消、插件停用、请求超时、上下文/媒体容量限制仍有效，不自动重试外部动作。独立执行档案记录步骤、结果和用量；只读工具inspect_execution允许模型自行按需查看当前会话记录，不要求用户先问。档案不进入日常记忆或自动上下文，读出的片段仅用于当前任务。最终回复及用量落盘后更新上下文状态；当前机制不再接着运行旧长期认知整理。流式片段可能先到界面，但完整会话操作尚未结束。

插件直接调用ctx.llm.chat则只走模型请求，不经过完整会话链路；不能将其记忆和统计与sessions.run混为一谈。

### 3.3 已采用的设计选择

| 选择 | 解决什么问题 | 当前边界 |
| --- | --- | --- |
| 连接、模型、用途绑定分开 | 一个API连接管理多个模型，用户明确选用 | 自定义协议由插件执行，不扩大核心模型业务 |
| 人格与会话分开 | 切换角色不丢经历、不增生会话 | 人格历史隔离仍可显式选择 |
| 原文与日记分开 | 原文持续可查，日记绑定固定来源与版本 | 文件读取与索引规模仍有限制 |
| 自动日记明确开关 | 默认不生成；开启后按容量逐篇追加，关闭后已有有效日记继续使用 | 目标占比是估算，语义质量不能仅凭格式校验保证 |
| 插件经受管理接口接入 | 复用人格/记忆，平台行为留在插件 | 独立执行与版本化契约，不是恶意代码安全沙箱 |
| 来源与结果分开 | 知道经历来自哪里，不把排队当完成 | 实际平台结果仍靠插件准确报告 |
| 写入排队和原子替换 | 减少并发覆盖、半写入，恢复时挡住新工作 | 不构成跨文件和外部平台的整体事务 |
| 冻结样本与演示分开 | 主干更新时验证旧插件原样可用 | 版本检查与行为回归并行，不能证明所有未来插件 |

隔离保护的是主干可继续运行，不是保证每次外部操作成功。进程终止不能撤销已经发生的外部行为；整机资源耗尽、恶意文件操作、插件另起的外部进程仍超出当前保护范围。

index集中组装核心服务，Sessions复用模型、记忆和工具；Runtime提供生命周期门面，隔离层仅传送公开调用和数据。插件不持有核心实现对象，logger等不暴露私有字段。内部仍有动态编排，但公开类型、版本检查和冻结契约测试共同约束兼容；不能借内部重构要求插件改代码。

### 3.4 生命周期

用户启停选择与实际状态分开。父插件或依赖不可用时相关插件等待，保留原开关；重新启用时恢复注册，旧实例不能发起新工作。

关闭主干先通知并取消会话、渠道及插件，再等待Web处理器、会话/渠道操作、事件和记忆写队列。安装插件清理有时限，不配合的进程会被终止，其未完成RPC拒绝，避免无限等待。核心仍等待已开始的持久化写入，不能靠丢弃记忆队列加快退出。具体超时默认值及配置见PLUGINS。

## 7. 后续开发保持一致的方式

GitHub 发布按 [RELEASING.md](RELEASING.md) 统一分工：开发会话交付实现、验证和本地提交，专门发布会话负责范围审查、隐私/许可检查及远端推送；不把其他会话的未交付改动一并发布。

1. **先定位再改。** 从本文确定能力归属和已有调用链；先给出当前行为及最小改动范围，不临时扩出一串前置项目。
2. **在责任方修复。** 保留调用方，补最小复现，再修改违反契约的模块。必须跨边界调整时先明确旧行为如何保留，不能多项目一起改来凑通过。
3. **实现和验证一起交付。** 检查实际调用、落盘和失败路径，不只看页面能保存；测试受影响范围，保留旧插件原样验收。
4. **维护现状，不追加对话流水。** 解决的问题移出问题表、并入能力说明；接口细节更新PLUGINS，记忆算法更新MEMORY，现有渠道更新CHANNELS。阶段报告仅保留证据。
5. **报告准确。** 写规则、加测试、功能落地、部署、真实平台验证分开说；未验证不称已验收。暂停实现时不借文档整理重构代码。
