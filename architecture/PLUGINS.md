# 插件扩展契约

本文描述当前实现。插件作者以本文、`core/context.ts` 和可运行示例为入口，不依赖私有设计稿，也不需要修改核心菜单、平台判断或记忆结构。

整体能力、调用链、代码分工和实现限制统一见 [STATUS.md](STATUS.md)，首次接手先读该文档。本文专门维护插件契约，不是另一份开发待办。以下职责与兼容规则是主干、插件和示例共同遵守的发布条件；规则不代表所有隔离机制已经实现。

## 不许越权开发

**用户没有授权的功能、项目或动作，无论什么理由都不许做。需要扩大范围，就先取得用户对新增范围的明确授权；获得授权之前不能开始写。**

这是开发权限，不是技术建议。本文后面的公开服务、可选依赖、职责划分和实现示例，只说明技术上如何接入，不能给任何会话或代理授予修改权限。

1. **先确定自己能改什么。** 写文件前，从用户原话、已有授权和用户确认的分工中确定：要做的功能、允许修改的插件或仓库、允许执行的动作。将这些范围记入现有工作记录或交接。不能确定时先问，可以继续只读核实；不能自己猜一个仓库开工。
2. **总目标不是无限授权。** “实现这个功能”“能做就做”“继续”沿用已经确定的范围，不等于“所有相关代码随便改”。用户在问题中提到 B 站、QQ 或某个接口，只是在说明需求，不自动授权修改这些项目。
3. **依赖缺口不能自行补到别人的项目。** 本插件缺少主干或其他插件的能力时，可以只读检查公开契约，说明缺什么、影响什么、应由哪一方提供。未经用户明确扩大范围，不得修改对方项目，也不得偷偷增加隐藏入口或兼容补丁。仍可继续完成原范围内不依赖该缺口的工作。
4. **所有写入都受范围约束。** 不只业务代码；测试、说明文档、manifest、版本号、锁文件、依赖、构建产物、安装副本、配置和数据同样受约束。不能用“只是辅助修改”绕过去。
5. **开发环境也没有例外。** 只改源码、不提交、不推送、不部署、另建分支或工作树、默认关闭新功能，都不能使越权修改变成允许。先做出来让用户看、被反对再回滚，也不允许。
6. **不能通过代理绕过。** 子代理、其他会话、脚本及自动工具继承当前授权边界。创建一个“负责另一插件”的子任务不会产生用户授权；不能委托别人做自己无权做的事。
7. **动作权限不能串用。** 只要求调研、评审或方案时，不开始实现；只要求修改文档时，不改业务代码。已授权的开发不自动授权安装、重载、真实账号测试、外发、push或Release。已有授权仍有效，在同一范围内不反复询问。
8. **禁止给自己补授权。** 不能以效率、最佳实践、测试通过、改动很小、修复必须如此、用户会受益或任务必须完成为理由破例。不能在功能开发中顺手改这些规则，让自己的越界行为显得合规。用户明确要求修改规范时，只按该文档任务修改。
9. **发现越界就停。** 立即停止越界工作，说明实际已改的范围，不继续完善或部署。用户要求回滚时，核对并撤销自己的改动，包括版本、文档和构建副本；保留他人的修改和用户数据。不得用删除记录掩盖越界。

例子：用户只授权修改 QQ 插件，即使要分享 B 站视频，也不能顺手改 B 站插件。反过来也一样。公开服务允许双方协作，但不表示当前会话可以改双方仓库。只有用户明确授权新的项目和范围后，才能在新的授权范围内继续。

## 设计原则

WhaleLife 是独立于交流平台的机器人。主干的职责固定为五项：模型 API 配置；LLM 人格、会话和记忆；插件运行与调用；日志和权限；统一配置及管理入口。驱动人格、记忆和工具的 LLM 链路及既有 token 统计包含在这些职责中。

平台接入、外部投递、主动性、意图、计划、语音/图像等能力、向量召回及业务策略由插件实现。允许配置某类模型，不等于主干必须实现其业务。主干不包含具体平台条件分支，也不依赖任何具体扩展插件。

现有 `ctx.channels` 已包含部分发送、回执和重试行为；这是现状，不是继续扩大核心职责的依据。如将这些实现移到插件辅助库，必须保留既有公开入口与行为，不能要求渠道插件同步改代码。

会话承载持续经历，切换人格不创建会话。各会话默认独立，可显式共享上下文或记忆空间。共享事实仅用户可编辑；模型只能编辑本会话的独立事实，整份正文硬限制100个Unicode码点。经历记录来源和实际结果；意图、计划及自主执行策略由主动性插件引入，未安装时核心不运行自主意图循环。

插件自行决定模型调用时机、频率、预算、是否限额、超额处理及重试策略。核心不统一扣减或限制插件额度。核心聊天和记忆整理有各自的统计；插件直接调用 `ctx.llm` 不会自动纳入会话账本，用量由返回值交给插件处理。

`ctx.llm.chat()` 的返回值可选增加 `finish_reason`：服务商提供结束原因时返回，`length` 表示生成被截断；未知原因归一为 `unknown`，未提供时省略。已有 `text/toolCalls/usage/reasoning_content` 语义不变，插件自行决定如何处理截断。主干的记忆整理会拒绝提交截断结果；普通聊天和插件直接调用不自动重试或改变思考设置。

## 会话工具顺序

主干首次记录可用工具时按函数名排列，以后同一批新增的工具按名称追加在末尾。插件停用期间不发送其工具，重新启用后同名工具回到原有顺位。主干重启后从 `config/tool-order.json` 恢复顺序。注册工具时请使用稳定的名称；改名会作为新工具追加。插件直接调用 `ctx.llm.chat()` 时自带的工具清单独立处理。

## 临时工具内容与持久回执

普通 `ctx.tools.register` 的返回、事件和默认记忆行为不变。需要让外部资料仅供当轮理解的工具，使用新增的 `ctx.tools.registerTransient`；先检查 `typeof ctx.tools.registerTransient === "function"`。旧宿主缺少时仅停用相关能力，不能回退到普通register。

```ts
ctx.tools.registerTransient<{ ref: string }, { text: string }, { action: string; target: string }>({
  name: "read_external", description: "读取资料供本轮理解",
  schema: { ref: { type: "string" } }, danger: "safe",
  async run(args, session) {
    const text = await readExternal(args.ref, session.signal); // 插件自己的实现
    return { content: { text }, receipt: { action: "read", target: args.ref } };
  },
});
```

- `run`必须返回`{content,receipt}`。content沿既有工具JSON链传给当轮模型；`tools.call`仍返回`{ok,result}`，result为content。这个接口不自动增加主干多模态能力，图片理解和媒体临时文件清理由插件负责。普通工具碰巧返回同名字段不会触发此契约。
- receipt由插件筛选，只放自己的动作、必要目标标识、自己的正文和真实结果，不能放第三方正文、图片或描述。必须为JSON，最多64KiB、20层；null表示不生成经历。函数返回成功不代表平台动作成功，sent/uncertain及真实平台ID仍由插件核实。原始工具档案保留最小调用状态。
- 从本轮请求调用临时工具开始（同批工具也保守处理），后续参数不写历史或日志。原始工具历史、`tool/called`、自动经历只接收receipt；该轮普通工具没有receipt时仅保留状态。事件增加`transient:true`，result为receipt或null，调用ID保存为散列标识；模型协议仍使用原ID。
- 后续工具的可信`ToolSession.transientContext`为true。主干独立事实写入工具在该轮拒绝写入，检索不保存临时query，避免模型复制资料绕过隔离。插件显式调用recordExperience/saveDocument、私有存储、日志或其他服务仍由插件负责筛选；主干不是不可信代码沙箱，也不能判断任意文字是否引用原文。
- **2026-11-07按用户确认调整保存边界：** 普通Web/渠道聊天及sessions.run/enqueue的最终助手正文是主要对话历史，正常保存，包含提问、约定和实际说给用户的引用。临时工具内容不等于聊天正文；不再因调用过临时工具而抹掉整条回复。工具原始content、随后参数和检索query仍不自动落盘，事实写入限制不变。明确使用runTransient/enqueueTransient进行技术执行时，临时输入仍不保存；若该执行使用临时工具，最终正文继续按旧契约不自动持久化，审计占位不参与对话上下文/召回。
- 普通渠道最终聊天正文正常存入投递回执，不再仅因使用临时工具添加OutgoingMessage/ChannelResult的`transient:true`；重复入站返回已有回复，不重复发送，显式retry只重投递已生成的正文，不重跑模型或工具。旧临时投递记录仍不恢复丢失正文、不允许重放工具。工具回执、临时参数和失败原始错误的隔离不变。
- 工具自动经历投影保留为审计记录，标记tool_trace，退出日常列表/检索/共享召回。插件通过recordExperience明确记录的实际业务结果保留；后台动作应使用该已有接口给出简短、带来源和outcome的经历，不依赖主干把整个工具JSON猜成成功结果。旧自动投影只在与实际工具档案完全匹配时排除，不改写旧文件。上述用户指定的保存行为调整不改变工具注册、调用返回值或事件结构。
- 停用、取消和重启不恢复临时正文；已完成动作的有效receipt仍保存，不伪装撤销或自动补做。临时工具异常及无效投影只返回/记录不含原文的错误。调用方不得把完整返回值重新写成普通历史，不能靠提示词“不记住”替代隔离。

接入验收见`tests/transient-tools.test.ts`：跨进程当轮可见、磁盘/日志/事件无临时标记、后续参数/回复/事实复制保护、用量、摘要、下一轮、停用/取消/重启和渠道不重放。此能力与runTransient互补，后者仅改变输入持久化。

## 执行轮次与按需排查档案

2026-11-07按用户确认取消完整会话的固定六轮工具上限。模型根据任务结果决定继续调用或结束答复，系统提示要求复用结果、完成后及时收尾、明确受阻或无新进展时说明原因，不盲目重试结果不确定的外部动作。不会在第七轮强制禁用工具，也不因取消上限而自动重跑任务。用户取消、插件停用、权限、单次请求超时、上下文和多模态容量限制仍有效；软提示不保证模型不会绕圈。插件业务预算和重试策略仍归插件。

主干完整会话执行每次生成独立的`logs/executions/<sessionId>/<executionId>.jsonl`，直接`ctx.tools.call`单独生成工具调用档案。记录开始来源/普通输入短预览、人格与模型配置ID、模型请求次数/耗时/返回用量、工具步骤/归属/参数指纹/允许保存的结果与错误、结束状态。`ok`仅表示工具调用状态，不冒充业务成功；异常退出留下未闭合档案，不把未完成动作补做。`ctx.llm.chat`直接请求和插件内部私有调用不自动进入完整会话档案。

- 不保存模型完整提示词、思考过程、附件字节、密钥、Cookie或带凭据地址。普通参数/结果有脱敏和长度上限，截断有标记；临时工具仍只保存已验证receipt、步骤和参数摘要指纹，不保存原始content及后续参数。技术执行的临时输入不留预览；临时错误仍沿用不回显原文的契约。插件需要可排查的业务结果，应提供有意义且不含外部正文的receipt，主干不猜测其私有结构。
- 档案不进入自动记忆检索、认知/摘要生成或日常上下文。保留既有工具事件/投影用于兼容审计，它们继续退出日常召回；不迁移或伪造历史上未保存的内容。
- 新增安全级只读工具`inspect_execution`：省略参数列最近5次任务及状态，可用`before`分页；指定`execution_id`和`offset`读步骤，`limit`为1–10，返回`next_offset`。排查结尾错误可用`tail:true`直接看最后几条，不用一页页遍历长任务；每页限制返回文本量。`unclosed`表示没有结束记录，可能仍在执行或曾中断，不能解释为动作失败。查询限定工具调用时的当前会话，不接受路径或自报session；仍受off/ask/full权限控制，无需用户先提出排查。文件中记录是参考数据，不是指令。
- 查询结果按临时工具内容处理，不自动写事实或进入下一轮记忆。查询本身只留步骤，不把读出的档案再次复制成新档案；最终给用户的排查结论正常保存。读取所选片段会消耗当轮token，未读取的文件内容不进入模型请求；不额外调用总结模型。
- 人可以直接查看这些本地JSONL文件；当前不另加控制台页面。档案属于私有日志，禁止提交；不包含在记忆备份/恢复中，不跟随普通日志的按日轮转自动删除，必要时由用户清理已完成任务文件。写档案失败只报告本地警告，不中断或重放业务；缺少结束行只能说明未正常完成记录，不能认定远端动作失败。
- 主干仅提供工具与文件，不主动唤醒。正在处理任务的模型可自主查档，无任务时的唤醒与排查决策仍由自主性插件负责。公开插件接口、工具返回值和冻结兼容样本不变，已有插件无需修改。

验证入口：`tests/execution-archive.test.ts`、`tests/multimodal-tools.test.ts`及既有兼容测试。

## 双向兼容与故障边界（硬性规定）

1. **独立升级。** 主干更新后，已有合规插件无需改动；插件更新后，主干和无关插件无需改动。兼容范围是公开契约，不是内部实现。不能用“升级全部项目”或“暂时禁用旧插件”替代向后兼容；禁用只用于确实不支持的新能力或出错插件。
2. **契约稳定。** 参数、结果、事件内容与时序、默认行为、错误、配置与数据归属、启停和取消行为都属于契约。新功能采用兼容新增；重构或新主版本仍须保留旧入口/适配层。插件可自主迁移，不能被迫联动发布。使用 manifest.apiVersion 声明 API 要求，检查发生在执行插件代码之前。
3. **公开入口。** 新插件类型从 `whalelife` 包公开导出导入；历史 `core/context.ts` 类型入口继续兼容。运行时只使用文档规定的 `ctx` 接口和已声明的插件服务。禁止导入主干内部实现、修改共享对象、读写其他组件的私有数据，或依赖控制台内部 API、CSS、DOM。`get()` 能取到一个对象不等于它的所有内部字段都是公开契约。
4. **各自拥有数据。** 主干迁移自己的数据时保持插件可见语义，插件迁移自己的私有配置和扩展 payload；双方不得直接改写对方结构。普通升级不能要求删库、重配账号或重装插件。跨插件服务也必须声明稳定契约并承担兼容责任。
5. **失败限制在责任范围内。** 插件受管理的加载、工具、事件和页面异常必须有归属、日志和资源清理；允许暂停明确依赖它的功能，不能导致主干及无关插件失效。未声明依赖的插件之间不得形成隐式联系。调用方仍需处理失败结果，不能把失败解释为成功。
6. **不能用改测试掩盖破坏。** 主干改动必须运行未修改的历史插件样本与原有断言；插件改动要在声明支持的最低宿主与当前宿主上测试。修复发生在违反契约的一方。新契约另加样本，禁止修改/删除旧样本、变更摘要值或弱化旧断言来迁就新实现。兼容测试失败不得合并或发布。

故障验收以**主干能切割故障插件**为准：先撤销该实例的全部入口并拒绝新调用，取消在途任务，限时清理；故障插件不配合也不能无限拖住主干。仅暂停故障插件及明确依赖它的功能，无关插件与核心聊天、记忆、控制台继续工作。配置、历史和故障日志保留；修复后可单独启用，不能自动重放结果不确定的外部动作。主干负责执行切割，插件负责登记资源、响应取消和处理自身业务错误。发现错误但无法停止其影响，不算完成；不能用单纯发出取消信号代替切割成功的验证。

当前可执行入口为 `npm run test:compat`（Node 24），与 `npm run check` 一起作为交付检查命令。CI 工作流已准备但未部署：现有 GitHub 凭据没有 workflow 权限，不能宣称远端已自动执行或强制阻止合并。`tests/fixtures/plugin-contract/2026-10-29/` 是首份冻结样本，覆盖范围以对应测试为准；日期是验收基线，不是加载器 API 版本。可维护示例与历史样本分开，未来增加功能不能悄悄改变旧插件。这套测试并未覆盖所有未来插件，也尚未建立多个已发布宿主版本的测试矩阵。

**执行边界：** 每个已安装插件有独立子进程，子进程内的 worker 执行插件，转发层保留旧同步接口语义。未捕获的工具、页面、事件异常、调用超时、心跳失联、退出及 V8 堆耗尽会使所属插件失败、撤销入口并终止其进程；明确依赖的插件暂停，无关插件继续工作。停止不改变私有数据，故障不改用户启停选择，也不自动重放外部动作。插件仍是可信本机代码；隔离不限制它直接访问操作系统，不保证抵御恶意插件、原生内存耗尽、耗尽磁盘或自行启动的外部进程。

公开类型来自独立的 plugin-api.ts 数据契约，经包入口导出，不再把核心实现类当插件接口。动态第三方 get<T>() 保留历史兼容；应通过泛型或 PluginServices 扩展声明自己的服务类型。

## 安装、归属与停用

`plugins/<id>/plugin.yaml` + `index.ts`，导出 `apply(ctx)`。配置位于本插件 `data/`，读取与保存使用 `ctx.config.read(file?)`、`ctx.config.save(file,value)`；缺省文件为manifest配置或`config.json`。JSON损坏会记录日志并读为空对象，插件要校验字段、呈现初始化状态，不能静默填入真实账号或替用户选择模型。

manifest 必填 id/name/version/description，可选 depends/optionalDepends/config/apiVersion。当前 API 为 1.0.0；apiVersion 可填 `1`、`1.x`、最低同主版本 `1.0.0`、`^1.0.0` 或同次版本的 `~1.0.0`。省略按 1.x，已有插件无需补字段。未知主版本、宿主尚未支持的最低版本及无效表达式在 import 前拒绝；包的 version 是插件自身版本。ctx.apiVersion 返回实际宿主 API 版本。未来升级须保留旧版本适配能力，版本检查不能替代行为兼容测试。

YAML 中写 `apiVersion: "1"`，必须是字符串。用较新接口时声明对应最低版本；版本号并不会赋予权限或自动安装依赖。

每次启用/重载会创建新进程，静态 import 的子模块也会重新加载，data 保留。配置读取、服务方法、事件、工具、渠道和页面均经过生命周期管理；不要依赖对象地址、原型链或跨插件共享模块全局变量。

用 `ctx.provide/get` 暴露和使用插件服务，manifest的 `depends` 声明必需依赖。停用选择会持久化；父子与依赖级联的规则见README。插件能力接口绑定完整插件ID；`ctx.get('web'|'tools'|'llm'|'memory'|'channels'|'models'|'personas'|'sessions')` 与对应属性使用同一封装。

### 可选服务接入（2026-11-02兼容新增）

扩展插件可用 `optionalDepends: [media-library]` 声明可选的**服务名称**，通过 `ctx.optional<T>(name, onChange)` 接入。服务可以缺失或稍后启动；提供者停止、失败或重载只撤销该连接，不将消费者整体停用。恢复后绑定新实例，无额外插件条目，不自动调用业务方法或重放外部操作。服务提供者无需修改原有provide或服务方法。

```yaml
optionalDepends: [media-library]
```

```ts
import type { Context } from 'whalelife';
type MediaLibrary = { describe(id: string, signal: AbortSignal): Promise<string> };
export function apply(ctx: Context) {
  // 旧宿主缺少入口时保留基本功能；不要用get(false)冒充可选连接。
  if (typeof ctx.optional !== 'function') return;
  ctx.optional<MediaLibrary>('media-library', binding => {
    if (!binding) return; // 未安装或已下线
    binding.effect(() => ctx.tools.register({
      name: 'describe_optional_media', description: '描述指定素材',
      schema: { type: 'object', properties: { id: { type: 'string' } }, required: ['id'] },
      async run(args: { id: string }, session) {
        try {
          const signal = session.signal ? AbortSignal.any([binding.signal, session.signal]) : binding.signal;
          return { text: await binding.service.describe(args.id, signal) };
        } catch { return { error: '素材服务不可用，请稍后重新选择操作' }; }
      },
    }));
  });
}
```

- 订阅返回幂等取消函数，也随消费者退出自动释放。首次及状态变化后异步回调，服务不可用时为undefined，可用时为`OptionalService<T>`；快速启停可以合并过期通知，回调按订阅串行。不要等待状态回调完成才让apply结束。
- `binding.service`提供当前实例的字段和方法；连接失效时，已保存的方法、嵌套服务引用也拒绝新调用，不能悄悄转到新实例。只读连接不允许给服务对象赋值。服务范围沿用get的父级局部/全局规则，仅用于扩展服务；主干能力继续使用ctx.models、ctx.memory等公开封装，不经此入口暴露内部实现。
- `binding.signal`在提供者失效、取消订阅或消费者退出时取消。宿主立即拒绝该连接的在途等待；服务支持signal参数时，调用方须按它自己的公开签名传入此signal，才能协同停止内部工作。宿主不猜测任意服务的参数，也不能撤回已经发生的远端动作。
- `binding.effect(() => disposer)`接受同步资源创建，返回清理函数或带dispose的对象，行为与ctx.effect相近，但生命周期限定于**本次连接**；保留对象身份，清理幂等。相关工具、页面、事件、定时器都应登记在这里。不要用ctx.effect登记仅属于可选能力的资源，也不要在异步回调恢复后绕过binding.effect注册入口；旧连接的effect会拒绝迟到创建。
- 先撤销旧连接并清理其资源，再通知新连接。宿主资源的原始清理函数可直接撤销工具/页面；插件自有清理及回调在独立进程执行，按stopTimeoutMs限时。回调正常时限为callTimeoutMs，连接失效后只给stopTimeoutMs退出；不配合或未处理异常归属消费者并切割它，不拖住提供者或无关插件。消费者仍应处理可恢复的业务错误。
- optionalDepends不阻止插件启动；非法声明、与depends重叠在导入前拒绝。使用ctx.optional时必须声明对应服务。**已有depends/get完全不变**，get(false)成功取得服务仍产生强依赖，即使同名服务写在optionalDepends里也不例外。
- 使用前检测`typeof ctx.optional === 'function'`，不要凭仍为1.0.0的apiVersion猜测新增方法。迁移旧桥接时保留原公开接口、用户启停选择及旧宿主路径，避免同时注册两套处理器；主干不会自动改动或删除已安装桥接插件。

### 通用资源与执行边界

`ctx.signal` 在停用、加载失败、重载旧实例和核心关闭时取消。定时器、连接、文件句柄和异步工作要通过 `ctx.effect(() => cleanup)` 管理，并将signal传到自己的请求。模型请求、工具执行和插件Web处理器已传递signal。旧实例不能继续注册入口、保存配置或发起模型调用；旧回调的迟到失败不会误停新实例。

完整执行权限不构成操作系统提权。核心无法强制撤回已经发生的外部操作；强制终止只表示停止本地执行，不表示外部调用未发生。工具实际返回成功就记录成功，不能因停用伪报撤销。插件应捕获可恢复的业务错误并返回明确结果，未处理异常会触发切割。

宿主 config.json 可选 plugin_runtime：startupTimeoutMs 默认15000、callTimeoutMs 默认600000、heartbeatTimeoutMs 默认5000、stopTimeoutMs 默认1000、maxOldGenerationSizeMb 默认256。时间单位毫秒，堆单位MiB；长请求按业务需要配置宿主时限，外部请求仍应设置自己的超时。调用时限覆盖工具、事件、服务及页面处理，包含响应已结束但处理器仍未返回的情况。停用先取消和撤销入口，清理超时后终止进程；这些是执行保护，不是插件额度或预算管理。

## 设置页与独立页面

```ts
ctx.web.page('/plugins/example/settings', (req, res, { signal }) => {
  res.setHeader('Content-Type', 'text/html; charset=utf-8');
  res.end('插件自己的设置页面');
}, { title: '示例设置', settings: true, navigation: true });

ctx.web.api('/plugins/example/config', async (req, res, { signal }) => {
  // 解析并限制请求大小、校验字段、读写 ctx.config，最后 res.end(...)
});
```

第三参数可选。`settings:true` 在插件卡片添加设置按钮（每个插件一个）；`navigation:true` 添加侧栏入口。两者可独立使用。页面在控制台内展示，页面内容和表单由插件负责。未注册页面的插件不显示空设置按钮。静态脚本、样式等也可用无入口参数的 `page` 注册。

路径必须在 `/plugins/<完整插件ID>/` 下，不包含查询串、编码绕行或路径跳转。请求按pathname匹配，查询参数从`req.url`读取。全部继承控制台登录和来源校验；页面和接口在插件停用/失败时撤销，进行中的请求收到signal。控制台刷新、切页或重新聚焦会更新入口；设置页内普通聚焦同步不会重载表单。

handler使用Node的`(req,res,{signal})`，不是框架请求上下文。插件负责请求大小、参数校验、响应类型、转义用户内容和密钥展示；不要另开无鉴权管理端口。iframe是页面容器，不能当作不可信插件的隔离沙箱。

处理器在插件进程内收到真实 Node 请求/响应流。主干先鉴权，再经仅监听本机、带内部随机认证的转发通道传送；内部认证头不交给页面处理器或浏览器。保留方法、URL、正文流、状态码、普通头和 trailers；浏览器断开及停用会取消请求。req.socket 是本机转发连接，不能作为用户身份依据。

完整可运行示例：`examples/plugins/contract-check/`，不会自动装进正式plugins目录。

### 父插件收纳子插件（2026-11-02兼容新增）

父插件在自己的plugin.yaml声明：

```yaml
console:
  groupChildren: true
```

这是控制台展示元数据，不改变运行记录、依赖、权限、进程、启停选择或配置存储。省略或false沿用旧的平铺展示；旧宿主忽略此字段，继续显示独立入口。新宿主对明确设置的非布尔值报错，避免误把字符串"false"当作启用。

- 插件管理外层只列父插件卡片，通过“打开 / 管理”进入父级工作区。工作区顶部横向切换“父插件设置”和“子插件”，内容使用完整宽度，不再叠加第二层侧栏。插件总数仍统计所有扩展，另外显示入口数，不把收纳后的数量当运行数量。
- 按完整插件ID的路径层级归属，收纳所有后代，多级子插件的切换标签显示祖先名称路径；最外层已声明父级优先。主干没有QQ或其他平台分支。父级缺失时回退到最近有效收纳父级，找不到则恢复独立卡片与原页面入口，避免隐藏孤立插件。
- 侧栏依旧只使用navigation:true页面；属于同一收纳父级的入口合为一个父级名称。父级无导航页但子级有时，也提供父级工作区入口；全组都没有可用导航页时，仍从插件管理进入。settings/navigation原有含义和页面注册返回值不变。
- 工作区以父/子插件的真实ID执行启用、停用、重载。当前插件状态与启停按钮常驻右上方；ID、版本、说明和重载位于更多菜单。stopped/blocked/failed仍有切换入口、状态、原因及管理按钮；故障原因直接显示，没有可用页面时不保留失效iframe。只有明确选择子插件才进入其页面，不把父级自带业务伪装成另一个子插件。
- 每个插件默认打开自己的设置页，否则使用自己的第一个导航页；有多个公开页面时显示页签。页面仍使用原owner、路径和鉴权。旧的`#extension:<编码路径>`链接继续工作，并显示所属父级；页面已撤销时按已安装插件最长路径匹配管理入口，不加载未经注册的URL。
- `#plugin:<编码完整ID>`进入插件管理工作区。浏览器刷新、返回保留所选插件；子页侧栏高亮父级。状态刷新更新管理区域时保留仍有效的iframe及未保存表单；显式切换插件、重载插件则重新加载页面。

QQ接入只需由QQ插件会话在**父插件**plugin.yaml加入上述声明，QQ空间继续保持原来的settings:true/navigation:true，不要提前关掉空间导航标志。无需修改空间业务页面、不新增私聊子插件、不调用私有控制台API，也无需迁移任何配置或记忆。插件会话自行将声明纳入发行包并按既有流程加载；主干不修改已安装插件manifest。

## 模型、人格与会话

| 接口 | 行为 |
| --- | --- |
| `ctx.models.list(type?)` | 读取已启用且配置有效的模型元数据；包含配置ID、名称、类型、提供商ID、上下文上限及callable；不返回密钥/连接凭据 |
| `ctx.models.connection(id)` | 后端读取指定模型的独立连接快照，包括协议、地址、密钥、代理、超时、参数、用途及上下文/向量维度；不发起模型请求 |
| `ctx.personas.list()` | 读取人格ID、名称、专用模型配置ID；不修改当前Web人格 |
| `ctx.llm.chat({model,messages,signal?,...})` | 使用明确选择的对话模型配置ID，返回text/toolCalls/usage；不隐式添加人格、记忆或执行工具 |
| `ctx.sessions.list()` | 已存在的未删除会话ID、名称、更新时间 |
| `ctx.sessions.create(name?)` | 显式创建空会话，返回ID |
| `ctx.sessions.current()` | 获取主干与Web共用的当前会话ID；没有选择时按下述规则初始化 |
| `ctx.sessions.context(id,persona)` | 当前指定人格下该会话的上下文与用量状态；兼容新增预计占比及日记状态，读取不改变当前会话 |
| `ctx.sessions.run({sessionId?,persona?,text,permission?,origin?,signal?,onChunk?})` | 省略sessionId使用当前会话，省略persona使用当前Web人格；走完整人格、记忆、模型、权限、工具及用量统计流程 |
| `ctx.sessions.runTransient(input)` | 参数与返回类型同run；text仅作为本轮插件输入，不保存为user消息，不持久化检索query；本轮工具续轮仍保留它 |
| `ctx.sessions.enqueue(input)` | 与run相同的完整会话，忙时进入主干统一会话队列；返回最终文本Promise<string> |
| `ctx.sessions.enqueueTransient(input)` | 与runTransient相同的临时输入，忙时排队；可在执行前重新判断有效性 |

`model` 是配置ID，不是提供商的裸模型名称。直接模型调用必须明确指定模型；会话调用遵循所选人格及已有模型配置。`callable` 表示可通过核心 chat 调用，仅 OpenAI 兼容协议的对话配置为 true；不能把 Embedding 或插件自定义协议交给 chat。

connection(id) 每次重新读取有效配置，拒绝不存在、停用或类型/服务不匹配的条目，不默认挑选第一项；结果修改不影响主干，后续读取可见用户保存的变化。返回字段为 id/name/model/type/provider_id/provider_name/protocol/base_url/api_key/proxy_url/timeout_seconds/parameters/dimensions/context_window。仅在插件后端使用 api_key，不写日志、不回传设置页。其他模型业务由插件根据 protocol 实现请求，并使用 signal、代理和超时；主干不代管业务预算/重试。自定义协议标识允许小写字母开头的1–64个字母、数字、点、短横线、下划线。未知协议可配置，核心不会伪装成能测试或执行它；不支持模型列表的服务手工填模型。

`sessions.run` 显式传入的会话必须存在且未删除，不自动创建未知ID，也不改变Web当前人格。一次run产生一次交流；自主插件如何形成意图、何时run、调用哪些工具都属于插件策略。`origin`可提供platform/action，核心注入真实插件归属。需要外部收发、稳定消息ID及重投去重时使用 `ctx.channels`，详见 [CHANNELS.md](CHANNELS.md)。直接run不替插件提供外部事件幂等。

`runTransient` 是兼容新增入口，使用前检查 `typeof ctx.sessions.runTransient === "function"`，旧宿主缺少时明确提示，不能回退到会污染历史的run。临时输入带真实插件来源及“不是真人发言”的明确标记，协议层使用user消息开启新一轮，但不保存为user历史。协议角色不代表实际来源。人格、既有记忆、权限、工具、取消、上下文预算、流式回调及用量沿用同一链路。结束/失败/取消后不进入原始聊天、未来历史、记忆候选或摘要材料。普通run和Web聊天默认持久化行为不变。

该入口仅改变输入持久化：助手最终文字及明确记录的实际业务经历默认仍按原契约保存；若显式调用registerTransient工具，另遵循本文技术执行的临时工具契约。自动工具投影仅供审计，不作日常回忆。返回值仍是Promise<string>；没有最终文字仍会报错，取消仍是取消，不因此被主干算作成功。角色实际决定由插件用recordExperience记录。插件的静默结束流程、是否执行及后续策略不由此入口代办。

思考模式工具协议：ChatReply与ChatMessage兼容新增可选reasoning_content。流式响应同时识别字符串reasoning别名，统一以reasoning_content返回；两者分别累计，标准字段优先（含显式空字符串），不重复拼接；null或非字符串不当作正文，完全缺失时仍省略。reasoning_tokens只保留为用量，不用于补造正文；结构化reasoning_details保留于原始诊断，不转换为协议思考文本。原始llm.chat调用者自行按供应商协议回传；完整sessions链路会收集流式原值，并在本轮每次工具续轮中原样携带，不作为onChunk文字、不自动存入经历或认知。本轮结束后丢弃，避免临时输入经思考数据进入未来记忆。对于DeepSeek（官方地址或deepseek模型名）以及明确thinking.type=enabled的兼容接口，启用工具时将已完成历史包装为带原角色、正文和来源的历史引用，不将缺少思考数据的旧assistant记录冒充未完成的协议续轮，默认不补造reasoning_content。历史仍受原上下文窗口与预算控制，引用转义开销和当轮思考字段均纳入请求预算。显式关闭thinking或无工具时保留普通历史消息表示。若此模式下工具响应未提供必须的字段，报出明确错误并停止该工具调用，不自动重试或关闭用户思考设置。规则依据[DeepSeek思考工具调用文档](https://api-docs.deepseek.com/guides/thinking_mode/#tool-calls)。

按模型可选配置 `reasoning_compatibility`，省略时上述默认行为不变。`response_field` 指向流式 `choices[0].delta` 内的字符串字段（支持有限安全点路径），`request_field` 指定 assistant 消息的回传字段；主干仍向插件返回统一的 `reasoning_content`。配置只在宿主本地转换协议，不作为模型请求参数发送。`models.connection()` 兼容新增同名可选属性，插件自行使用 SDK/HTTP 时自行决定是否适配；已有插件无须修改。空串、null、缺失分别处理，结构化签名或加密思考不能用文本映射替代。

`fill_missing: true` 是用户单独开启的“缺失思考字段补空（实验性）”：工具响应确实缺少思考文本时以空字符串尝试续轮，已有正文不覆盖；不补造工具参数、调用 ID 或用量，不自动重试或关闭思考，接口仍可能拒绝。默认保护不变，不把这一选项扩散到其他模型。思考内容及映射仅用于协议，不因此进入普通会话记忆。

控制台的 AI 辅助兼容配置只在用户点击时运行：以合成工具请求观察字段结构，让所选模型提出受限文本映射，再验证工具续轮。最多四次模型请求；仅使用本地固定结果测试工具，不执行插件、不加载人格或聊天历史、不自动保存。只有验证成功的映射可以填入草稿，保存后生效，AI 不会开启补空。诊断支持取消和并发保护；记录各次返回的真实用量，缺失用量不当作零。此功能验证特定接口在当次测试中的行为，不承诺未知中转或后续路由始终兼容。

模型HTTP错误只限量读取最多16 KiB、最多1秒的响应诊断，显示识别出的协议/认证/额度等类别、安全类型及格式合法的请求ID；未知正文不回显。不会把供应商任意错误正文、请求内容或密钥拼进日志。流式error帧使用同样规则。HTTP状态和外部取消语义保留，不自动重试失败调用。

```ts
const reply = await ctx.sessions.runTransient({
  sessionId, text: temporaryInstructions,
  origin: { action: "本轮检查" }, signal,
});
```

### 完整上下文、日记与容量状态（2026-11-08兼容新增）

`sessions.run/runTransient/enqueue/enqueueTransient` 保持现有签名、返回值、权限、队列、取消和持久化边界，按会话已保存的记忆策略执行。记忆使用有效日记与未覆盖的完整原文，没有日记时即为完整有效历史；容量不足时明确失败并保留原文，不按6000 token裁尾，不自动切换会话。新样例默认 `diary_enabled: false`，只有启用自动日记且达到容量阈值时，才将较早完整原文整理为一篇新日记。关闭开关停止今后生成，已有有效日记仍替代覆盖的原文；日记逐篇保留，不再次作为总结材料。当前机制不注入旧短期摘要/长期概览，也不执行旧认知生成或维护。

`ContextPolicy` 兼容新增可选 `diary_enabled` 自动生成开关，默认关闭；已有 `memory_mode: "full" / "diary"` 继续作为关闭/开启的兼容别名，显式新开关优先。`compression_trigger_percent` 默认80，`compression_target_percent` 默认50，均按“预计输入 + 输出预留”占模型总上下文容量计算，不按时间或条数触发。内部 `legacy` 承接未声明新开关却显式携带旧模式或旧字段的配置及调用；原有字段和既有插件语义保留，它不是界面模式。旧兼容策略的读取结果不新增开关字段，避免原样回写时改变旧语义。完整规则及明确迁移要求见[记忆系统](MEMORY.md#自动日记与触发)。

`SessionContext` 的原有 `usage` 仍表示匹配当前模型/人格的上次请求实际用量，缺失时为 `null`，不改成估算值；原有 `memory_window` 等字段继续返回。兼容新增字段如下，读取旧宿主响应时须允许缺失：

| 字段 | 含义 |
| --- | --- |
| `context_estimate` | 最新有效材料的预计输入、输出预留、总量与占比，`source: "estimate"`；容量未知时 `percent: null` |
| `diary` | `enabled` 表示自动生成开关；篇数、覆盖及剩余原文条数、字符数反映实际带入的日记，关闭自动生成不将这些计数清零；另有失效数、剩余整理额度及可选暂停原因和提示 |
| `model.limit_source` | `configured`、`provider` 或 `unknown`；手动上下文容量优先，服务容量须精确匹配模型 |

容量读取只使用明确的上下文总量元数据，不猜模型名称，不把输出上限当容量；元数据缺失或读取失败保持未知，可通过控制台手动填写。日记生成每次触发至多一次请求；非取消失败暂停该会话的当前历史范围，用户显式恢复后才再按阈值尝试，不由后续插件唤起反复自动重试。生成失败不删除原文、不重复外部动作；原始档案继续通过既有读取接口核对。旧摘要在当前机制中仅供查看。

### 临时多模态工具（2026-11-04兼容新增）

`ctx.tools.registerMultimodal` 把插件准备的文字和图片交给**当前会话正在使用的同一个模型**。它始终遵守上文临时工具持久化规则，返回 `{ content: ToolContentPart[], receipt: JSON | null }`。旧 `register` 和 `registerTransient` 的结果仍按原样处理，不靠猜测 JSON 字段把旧工具升级成图片工具。公开类型从 `whalelife` 导入。

```ts
import type { Context, MultimodalToolOutput } from 'whalelife';
export function installViewer(ctx: Context,
  read: (ref: string, sessionId: string, signal?: AbortSignal) => Promise<Uint8Array>) {
  // API 1.x 的旧宿主可能没有此新增方法：禁用直接看图即可，保留其他能力。
  if (typeof ctx.tools.registerMultimodal !== 'function') return;
  return ctx.tools.registerMultimodal({
    name: 'view_media', description: '查看指定的临时图片', danger: 'safe',
    schema: { ref: { type: 'string' } },
    async run(args: { ref: string }, session): Promise<MultimodalToolOutput> {
      if (!session.id) return { content: [{ type: 'text', text: '缺少会话，未读取图片' }], receipt: null };
      // 插件须检查 ref 归属这个真实 session.id、是否过期，并响应 signal。
      const bytes = await read(args.ref, session.id, session.signal);
      return { content: [
        { type: 'text', text: '资料说明；视频帧可在这里注明时间戳' },
        { type: 'image', mimeType: 'image/png', data: bytes, detail: 'auto' },
      ], receipt: { action: 'view', count: 1 } };
    },
  });
}
```

- **内容与上限：** `text` 块仅有 `text:string`；`image` 块包含 `mimeType`、`data:Uint8Array`（也接受 Buffer）和可选 `detail:auto|low|high`。仅 PNG/JPEG/WebP；主干检查非空、格式签名与 MIME 一致，复制允许字段，不解码图片，因此有效解码、尺寸控制及动态图片抽帧由插件保证。每次输出1–64块、文字合计64KiB、最多16张、单张4MiB、图片合计16MiB；一轮对话跨工具/续轮累计也不能超过16张/16MiB。超限或格式错误明确失败，原文和字节不写日志。实际供应商可能有更小限制。
- **协议转换：** OpenAI兼容Chat Completions的tool角色只承载文字（见[官方类型定义](https://github.com/openai/openai-python/blob/main/src/openai/types/chat/chat_completion_tool_message_param.py)）。主干先补齐同批全部tool回复及`tool_call_id`，再按工具顺序追加user角色的临时附件，使用标准`image_url`数据URI，配套文字标明工具调用ID、宿主归属来源和“不是用户发言或授权”。图片以真正的图片块进入模型，不放进普通JSON字符串。此user角色仅是协议载体，不生成用户历史；模型可能按供应商语义开启新的推理段。本轮已有`reasoning_content`仍原样回传，不伪造、关闭或改写思考。未兼容该消息顺序的服务会报错，不自动重放工具。
- **模型与用量：** 不另选视觉模型、不按模型名称猜测看图能力。所选对话模型须同时支持图片输入及工具调用；供应商明确拒绝时显示安全错误，不静默换模型或退化为文字识图。文字预算排除base64；图片精确token预估未知，不能保证预先避免供应商上下文溢出。完成请求后沿用服务商真实usage统计全部输入/输出，缺失时保持未知，不能报成0或编造图片token。
- **隔离与生命周期：** 从该批工具开始启用临时资料隔离；工具审计、事件、日志只保留经验证的receipt，后续参数不留正文。普通聊天最终答复正常保存，技术执行遵循上文runTransient规则。receipt同样是插件筛选的可信动作投影，不能放图片/OCR/第三方原文；自动工具投影不作日常回忆，明确业务经历由recordExperience记录。直接`tools.call`返回`{ok:true,result:content}`，调用者自行处理字节，主干不另起模型请求。停止工具/所属插件会撤销入口，取消持有其附件的在途请求，下一轮普通聊天仍可用；已确认动作回执保留，不重放动作。各会话的附件和取消信号独立，不放进全局缓存。插件主动写日志/记忆/私有存储不在自动隔离保证内。
- **能力边界：** 媒体引用、会话绑定、过期、下载、裁剪、解码、视频抽帧与时间戳都归插件；主干不访问URL或文件路径、不依赖具体插件、FFmpeg或图像库。首版没有原生视频或音频块；视频由插件提供带时间说明的图片序列。插件在旧宿主必须通过方法存在性检测显示“无法直接交给主模型看图”，禁止退回普通工具塞base64或擅自选另一模型。

专项测试 `tests/multimodal-tools.test.ts` 使用独立插件进程、合成图片和本地HTTP/SSE模型，覆盖协议、当前模型/人格、用量、隔离、跨会话、取消/停用、拒绝和上限；不代表对所有真实供应商的视频/视觉效果验收。

### 统一会话队列

Web、渠道receive以及新的enqueue/enqueueTransient共用按会话串行的调度。不同会话可并行，不把供应商或模型配置当作全局互斥资源。渠道的一次入站从生成到投递完成占用一个执行位；直接channels.send只走独立传输队列，当前工具可以等待真实发送回执，不会排到自身会话结束之后。

这是兼容新增能力：旧run/runTransient在会话忙时仍拒绝，依赖旧行为的插件无需修改；需要等待的插件显式改用enqueue/enqueueTransient。旧宿主应先检测方法是否存在，不要偷偷退回会污染记忆的run。原生渠道适配器使用receive会自动获得统一排队；自行用sessions.run驱动聊天的适配器需要主动选择enqueue。

SessionQueuedRun保留SessionRun全部字段，并增加三个可选字段：

| 字段 | 行为 |
| --- | --- |
| priority | -100到100整数，默认0；数值大的等待项先执行，同优先级按进入统一队列的顺序执行。不会中断在途请求。Web和渠道真人消息固定为0，不合并正文 |
| key | 1–128字符，只合并同一插件实例、同一会话内**尚在等待**的同键请求。首条输入/优先级/有效性检查保持不变，后来的调用等待同一结果；正在执行的同键任务可再保留一条待处理机会 |
| beforeRun | 开始执行、读取模型上下文前调用的函数，可返回boolean或Promise<boolean>；仅true继续，false或抛错则拒绝Promise，不调用模型或写入消息 |

signal在等待中取消会立即移除该项，不制造“已行动”或“未行动”经历；原始请求被取消时，同键跟随者也收到失败，跟随者取消只结束自己的等待。插件停用、卸载、切割或主干关闭会取消相应等待项，重新启用不继承旧实例队列。在途取消仍沿用模型/工具契约：执行位等真实操作结束后释放，已确认的外部结果照常记录，不能伪装撤销或自动重发。

请求在入队前固定会话、人格ID、权限、来源、主干接收时间和时区。用户后续切换会话不移动已排队输入；模型、人格正文及有效历史在真正执行时读取，因此可以看到刚完成的交流。需要因切换/时段等业务变化撤销的，由插件取消signal或在beforeRun返回false；主干不理解插件意图、定时器或插件ID。beforeRun应快速检查条件，不产生外部动作；不要在回调或当前会话工具中等待同一会话的新enqueue，否则形成自等待。工具发送使用channels.send，不重新receive同一条入站。

队列只在内存中保存：每会话最多128条等待项、全局最多1024条（不含执行中），超限明确拒绝，不静默丢弃真人消息。不持久化或在重启后自动重放。队列本身不产生模型用量；实际执行继续记录原有token统计。既有插件RPC调用期限（默认10分钟）、模型超时和故障切割仍有效，排队不提供无限时长或跨重启的任务保证；插件可用signal设置自己的等待期限。长期待办应由插件持久保存，再按用户授权提交新的判断机会，不能盲目重放结果不明的外部动作。

```ts
if (typeof ctx.sessions.enqueueTransient !== "function") throw Error("宿主缺少会话排队接口");
const sessionId = await ctx.sessions.current();
const text = await ctx.sessions.enqueueTransient({
  sessionId, text: temporaryInstructions, signal,
  key: "my-pending-opportunity", priority: -10,
  beforeRun: () => isStillValid(), // 业务有效性由本插件决定
  origin: { action: "本轮检查" },
});
```

### 渠道入站发言人

渠道 handle 提供可选能力标识 `supportsSenderProfile`。值为 `true` 时，`receive`、`openTurn`、`append` 接受 `senderProfile?: { nickname?: string; remark?: string }`，供模型区分同一会话里的不同发言人。账号归属、路由和权限继续使用原有认证与稳定 ID。逐条快照、旧宿主降级及调用示例见[入站发言人](CHANNELS.md#入站发言人)。

渠道 handle 的 `supportsImageInput === true` 表示这三个入口都可以携带临时图片。主模型明确不支持图片输入时，主干才调用适配器可选的 `describeImages`，并在原轮使用描述继续回复。[入站临时图片与示例](CHANNELS.md#入站临时图片)

### 渠道轮内追加（2026-11-08兼容新增）

渠道handle可选提供 `openTurn(message, {signal?}) -> Promise<ChannelTurn>`。插件先检测 `typeof channel.openTurn === "function"`；旧宿主降级为原 `receive` 逐条独立处理，或在必须依赖追加时提示能力缺失。普通 `receive`、`run/runTransient`、`enqueue/enqueueTransient` 保持原行为，不自动合并消息。

`ChannelTurn` 提供 `id`、`sessionId`、可选 `duplicate`，以及 `append(IncomingMessageData)`、`closeInput()`、`result()`。首条输入持久化后即可取得handle，任务由主干继续执行；`result()`返回最终 `ChannelResult` 的Promise，可重复等待，不关闭输入。`closeInput()`显式封口，已接纳的消息仍处理。提前确认平台收件不应调用它。字段、返回状态和示例详见[CHANNELS.md的轮内追加契约](CHANNELS.md#轮内追加输入2026-11-08兼容新增)。

追加仅允许同一注册账号、peer和sender，每条保留独立消息ID和实际接收时间；`append`返回 `{status: 'accepted'|'duplicate'|'closed'|'full'|'cancelled', messageId}`，格式、归属冲突和保存失败拒绝Promise。每轮最多128条/128000字符、每条最多16000字符，包含首条和已消费消息。等待执行、模型生成和工具执行期间均可追加；最终候选采用前原子封口，`closed`后的新消息必须另开一轮。

补充到达后保留已开始动作及真实结果，当前批次尚未开始的工具明确记为未执行，配对完成后再让模型结合补充判断；不会撤销或自动重放动作。无工具的旧候选不会保存或投递，本轮只产生一次最终回复。补充真人消息即使遇到临时工具也正常存为历史；思考字段及多模态附件保持本轮协议。首条与所有成员共用一个deliveryId，任一成员的重复入站或显式retry都引用同一最终结果，retry只重投已存正文。

输入先保存在各自的渠道回执，取消、插件停用或崩溃时保留核对依据，不自动重放模型、工具或投递。此入口不提供跨重启任务恢复，也不保证跨平台恰好一次投递。输入归并、外部收件确认和后续业务策略由插件决定，不增加平台分支或修改人格配置。

### 与Web共用当前会话

完整会话请求默认携带主干当前日期、时间、星期、时区及允许读取的历史时间信息；Web、`sessions.run`及渠道生成共用这条链路，工具调用后再次请求模型会刷新时间。插件无需自行注入系统时间，直接`llm.chat`保持原始调用语义。时间规则见[MEMORY.md](MEMORY.md)。

```ts
const sessionId = await ctx.sessions.current();
const text = await ctx.sessions.run({
  sessionId, // 固定本次交流及后续经历记录的目标；单次调用也可省略
  text: "接着聊刚才的事",
  origin: { platform: "我的平台", action: "接收消息" },
});
```

- 当前选择是整个工作空间共用的单一指针，保存在记忆索引 `current_session`，不是每个浏览器、账号或插件各一份。它只选择会话，不合并历史、不扩大跨会话记忆共享。
- Web在“使用配置”明确点击“切换会话”或“新建并使用”后，插件下一次默认调用读取该选择；切人格不建会话。记忆管理下拉框仅浏览档案，查看、编辑其他档案不会改变当前选择。插件的 `create` 和显式 `run` 仍不会切换全局选择。
- 首次迁移优先采用首个已登录浏览器提供的、确实存在且未删除的旧会话ID；否则采用最近更新的可用会话（更新时间相同按索引中后加入的优先）。只有没有任何可用会话才建一个空会话。未发送过消息、没有落盘的旧浏览器ID不视为已有会话。
- 一旦主干已有选择，旧浏览器缓存不能覆盖它。多窗口显式切换按服务端串行提交顺序最后一次生效；新网页发送时带预期当前ID，旧窗口误发会被拒绝并刷新。旧版显式WebSocket调用继续兼容。
- `current` 的选择与创建共用记忆写队列，并发首次调用只建一份。删除当前会话后，下次读取回退到最近可用会话；全部删除则新建，绝不复活删除记录。重启保留指针，恢复备份恢复备份中的选择，失效指针按同样规则处理。
- 每次完整调用在接收时确定人格、在解析当前选择时确定会话，后续切换不搬动正在回复或等待的输入。旧run/runTransient保留忙碌错误；enqueue系列及Web/渠道入站等待同一会话的执行位。维护、恢复、停用与取消会阻止相应新调用及尚未提交的排队操作。
- 需要将多步操作固定在同一会话时，先取 `const sessionId = await ctx.sessions.current()`，随后显式传给run、记忆等操作，不要在回复结束后重新读取并假定选择没变。
- 新插件使用前可检测 `typeof ctx.sessions.current === "function"`，旧宿主缺少该入口时给出明确要求。既有1.x插件不需迁移；不要靠读主干文件猜当前会话。

## 事件通知

`ctx.on(name,handler)` 返回可重复调用的解除订阅函数，并随插件卸载清理。通知异步派发，发生在来源操作提交之后，不持有记忆写锁；每个订阅收到独立数据副本。通知不是拦截器，不修改已经保存的消息，不等待插件完成才继续用户回复。

| 事件 | 载荷与时机 |
| --- | --- |
| `whalelife/ready` | `{at}`；启动就绪，之后启用的插件也会收到一次 |
| `whalelife/shutdown` | `{at}`；关闭前通知，随后signal取消；清理资源使用effect和signal |
| `channel/message` | 已保存的user消息，含id/session/来源/正文等；Web、外部渠道和插件会话共用 |
| `channel/reply` | 已保存的助手最终回复；表示生成完成，不等于外部投递成功 |
| `memory/recorded` | 已追加的原始事件；包含技术回执，订阅者须按type筛选 |
| `memory/updated` | `{session}`；事实、日记、旧认知或摘要状态已经写入，按需通过记忆接口读取 |
| `tool/called` | `{id,name,source,origin,session,ok,result,transient?}`；临时调用只返回持久receipt或null，其余保持原结果。业务完成状态仍由插件明确记录 |

插件通过 `ctx.emit('plugin:<自身完整ID>:<事件>', payload)` 发布自定义通知，不能冒充核心事件。通知不持久化、不重放，也不保证外部任务恰好一次执行；需恢复的业务状态通过插件配置、扩展记忆或私有数据保存。避免收到自己的记忆写入通知后无条件再次写入而形成循环。

事件处理错误会记录日志、隔离失败插件及清理其资源，不回滚已经提交的核心记录。插件应自行捕获可恢复的业务错误。

## 记忆与能力经历

历史技术输入可由其所属插件明确迁移：`ctx.memory.readSession(sessionId, limit?, beforeId?)`仍返回原始档案，limit最多100；新增beforeId表示读取该消息之前的一页，按原顺序返回，可用本页首条ID继续向前。默认两个参数行为不变，未知分页ID报错。

`ctx.memory.excludeInputs(sessionId, messageIds)`每次接受1–100个明确ID，仅允许本插件通过sessions.run存成的user输入（来源、channel和account均校验），不允许处理其他插件、Web或渠道的真人消息、助手回答、经历记录。原文不删除、不修改；返回`{excluded: 新增排除数量}`，重复请求不重复处理。插件负责识别自己的技术输入，不能按正文关键词或来源批量猜测；主干不会主动处理正式记录。活动轮次或渠道操作期间拒绝迁移，插件应暂停新唤起并等本轮结束后再处理。

排除对后续模型历史、上下文计数、普通/共享召回和整理资料生效。日记按固定来源ID及版本校验，仅引用了变化来源的篇目退出上下文，其他篇目继续有效；失效篇目对应的有效原文重新可用，不按字串清洗日记正文。既有摘要失效及自动认知退出上下文的兼容行为保留，原数据不删除；当前机制不会为了重建旧摘要/认知发起请求。不删除真实决定、工具结果或手工事实，也不猜测哪些真人回答/事实被旧提示间接影响。原始档案/API仍能读取被排除消息用于核对；不是物理删除或保密擦除。排除状态随会话备份恢复，迁移前可使用控制台备份。

`ctx.memory.recordExperience(sessionId, {event_id, outcome, text, origin?, occurred_at?})`允许注明事情发生时间。`occurred_at`必须为带时区的有效ISO日期时间，主干规范为UTC；省略时保留未知，不拿记录时间冒充事件时间。返回的`ts`仍为记录时间。同一事件/结果重投保持原记录，不能靠重投改时间；已有插件无需增加字段。

通过 `ctx.memory` 的公开接口检索、记录实际经历、注册和保存插件专属类型，详见 [MEMORY.md](MEMORY.md)。不要直接写会话内部状态文件或共享事实，不通过修改人格塞入平台来源。通用经历说明实际做了什么，带检索描述的插件扩展保存需要参与召回的内容。

向量召回及上下文缓存业务本轮未实现，也没有新增的向量/缓存提供者注册方法。稳定记录ID、日记schema与固定来源版本是数据边界；未来能力应在现有公开模型/记忆接口上兼容扩展，不能运行时导入主干日记模块、读写内部文件或把私有状态对象当插件协议。

不应自动进入记忆检索的意图文件等状态，使用 `readDocument(sessionId, key)` / `saveDocument(sessionId, {key, revision, data})`。接口按插件、会话隔离，提供原子保存和冲突检查；缺失返回 `{revision:null,data:null}`，首次保存才建文件。插件自定payload结构，例如 key为intents、data为`{schema:1,items:[]}`；主干没有意图工具、提示词、唤醒或执行逻辑。完整限制和备份语义见MEMORY.md的“会话文档”。新插件使用前检测接口是否存在；旧宿主不支持时明确提示，不能直接读写主干文件或偷偷改用自动召回的扩展记录。

```ts
const snapshot = await ctx.memory.readDocument(sessionId, "intents");
// 插件自行校验/迁移snapshot.data，再生成nextData；冲突时重读并按业务合并。
const saved = await ctx.memory.saveDocument(sessionId, {
  key: "intents", revision: snapshot.revision, data: nextData,
});
```

关闭插件会取消其注册能力并清理运行资源，已经产生的事实和经历仍然保留。重新启用同ID插件可读取自己的持久配置和扩展状态。

## 验收与边界

`tests/plugin-contract.test.ts` 将示例复制到临时plugins目录，通过真实boot验证入口、鉴权、配置保存、启停、模型/人格选择、同会话切人格、来源、token统计、记忆事件和重载代际隔离；使用模拟模型。`plugin-cancellation.test.ts` 用本机HTTP验证取消。`channel-rebinding.test.ts` 验证重绑、回执和恢复旧备份不重放。

核心关闭先通知并取消会话、渠道和插件，再等待受管理任务、限时插件清理及记忆队列。插件应配合signal和effect；不配合的安装插件会被终止，不能无限阻塞关闭。测试要覆盖迟到结果、异常、重复回调、父子/依赖停止与重启后的状态。只在临时目录测试，不把演示插件或验收事实装入正式环境。

RPC在异步调用的Promise结束前持有解码后的调用参数，保证传入的AbortSignal即使被接收方用AbortSignal.any合并，也不会因原始代理被垃圾回收而丢失取消。调用成功/失败后释放引用，连接关闭时也立即释放，不能将信号永久强引用到插件退出。此修复不改变公开签名、取消原因或已完成外部动作的回执，不需要插件修改调用方式。GC回归覆盖主干与插件两个方向、排队等待、执行、工具结束和直接模型调用，以及完成后的引用清理。

新建会话同时受记忆恢复屏障和生命周期约束，排队提交前会再次检查。Web关闭会等待已接收的插件handler结束；核心还会等待已经开始的事件handler，而不是仅关闭HTTP响应就退出。

当前核心聊天与渠道消息以文本为基础；其他模型协议、真实平台连接和主动性策略由插件实现。交互审批UI仍未实现；full 不依赖审批UI。隔离测试还覆盖启动/调用死循环、never Promise、process.exit、V8 OOM、HTTP与事件卡住、依赖阻断、完整子模块重载和故障后主干可用。测试通过只说明这些已覆盖场景，不是任意插件永不故障的保证。

## 可选诊断输出（2026-11-15）

宿主可通过本地配置开启独立诊断记录，插件无需修改。`ctx.llm.chat` 的宿主请求与工具调用可记录真实输入、输出和用量；临时正文只进入诊断目录，不因此写进普通记忆。`models.connection()` 后插件自行使用 SDK/HTTP 的请求仍不在宿主可见范围。诊断不是插件依赖、业务预算、重放或主动性接口，不向插件暴露诊断目录读写服务。采集失败不阻断原有调用。协议与边界见[DIAGNOSTICS.md](DIAGNOSTICS.md)。
